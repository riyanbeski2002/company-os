## Типографика

Типографика задаётся осью стиля `typeVoice` и семантическими токенами `font.*`, `weight.*`, `type.*` (контракт — ARCHITECTURE §2.3–2.4). Порядок в каждой главе: сначала универсальный закон для любого бренда, затем его заполнение у Higgsfield с пометкой «Пример (Higgsfield)». В коде: `HFT.theme({style, brand})` отдаёт готовые `type.*`, `HFT.fontLink(theme)` — ссылку Google Fonts на нужные веса и подмножества, `HFT.toCSSVars(theme)` — CSS-переменные, `HFT.validate(theme)` проверяет шкалу, пол, семейства и трекинг (V06–V11).

### Семейства, роли, лимиты

**Роли голосов** (одинаковы для любого бренда; конкретные шрифты приходят из `typeVoice` стиля или из `brandConfig.fonts {display, body, data, fallbackByScript}`):

| Голос | Что несёт | Токены |
|---|---|---|
| **Бренд-диктор** | титульное СЛОВО, claims, офферы, числа, теги, таймкоды, end card | `font.display`, `type.mega` / `type.display` / `type.headline` / `type.number` |
| **Голос продукта / keynote** | sentence-case заголовки, утверждения, colour cards, split-титулы | `font.text` (или `font.display`), `type.headline`, `type.subhead` |
| **UI** | prompt, чипы, логи, подписи, legal, субтитры | `font.text`, `type.ui`, `type.caption` |
| **Данные** (опц.) | счётчики, «PROMPT:», спеки | `font.mono`, `type.code` (`tnum`) |
| **Акцент** (опц.) | одно слово или один титул на фильм | `font.accent` |

**Лимиты.**
- [обязательно] 2 нарративных семейства + максимум 1 акцентный шрифт на фильм (на одно слово или один титул) + опционально моно для данных и кода [А+И]. Проверка `validate()` V10.
- [обязательно] **≤5 нарративных текстовых стилей на видео** (у Higgsfield — P2 «style lock»: 320/120/40/32/28). Считается только нарративная и дисплейная типографика: заголовки, СЛОВО, квалификаторы, числа, подписи, субтитры. Текст UI-клонов наследует шкалу продукта × масштаб клона и записывается в паспорт отдельной строкой.
- [обязательно] ≤3 уровня на кадр. **Соседние токены шкалы отличаются ≥×1,33** [И T. Brown 2011, модульная шкала]; **уровни, которые стоят в одном кадре, — ≥×2** [Vignelli, craft]. Проверки V08 и `policy.type.framePairs`.
- [обязательно] **В одном кадре никогда не бывает двух героических голосов; в одном фильме один ведущий голос.**
- [обязательно] Только Google Fonts (или файлы из `brandConfig.fonts` с проверенной лицензией). Сверить имя семейства, оси, веса и подмножества скриптов (V09); версию файла записать в паспорт.
- [по умолчанию] `weight.body` ≥500 для must-read текста на видео.
- [по умолчанию] Голос дисплея задаёт стиль или регистр кадра, а не то, «наш» это фильм или партнёрский.
- Дефолт внешней схемы tokens_universal (Inter + ui-monospace) не принимаем: системный моно не воспроизводится между машинами. Берём проверенные Google Fonts с fallback по скриптам (глава «Локализация и системы письма»).

**Файлы шрифтов** (версия фиксируется в паспорте):
- **Figma:** встроенные Google Fonts — Inter 4.x (включает Inter Display как opsz 32) и Space Grotesk (variable, wght 300–700).
- **After Effects:** установить те же файлы локально. Space Grotesk — variable TTF из Google Fonts. Inter — статические файлы Inter и Inter Display (релиз rsms/inter 4.x, OFL; тот же шрифт, что Inter в Google Fonts с осью opsz). На машине команды в `~/Library/Fonts` уже стоят Inter, Inter Display, Inter Tight и Space Grotesk variable.
- ⚠ Если версия AE не применяет оси variable-шрифта, используйте статические инстансы Space Grotesk.

### Шкала: вывод из пола, а не выбор

[обязательно] Шкала выводится из пола читаемости самой строгой площадки поставки, а не подбирается на глаз (ARCHITECTURE §3.7.6) [А+И+Э]:
1. base = `type.body` = round(floorX / xHeight(текстовый шрифт)).
2. steps[k] = base × ratio^k, ratio ≥1,333 (по настроению: 1,333 / 1,414 / 1,5 / 1,618).
3. headline = первая ступень, у которой высота буквы достигает **comfort** и строка из 18 знаков влезает в рабочую ширину.
4. display = headline + 2 ступени; mega = display + 2 ступени (≤680 px).
5. label = round(floorCap / capHeight); ui = max(20, 0,56 × base); code = base × xHeight(text) / xHeight(mono).

Пример, Inter в `feed16x9` при ratio 1,333: 64 · 85 · **114** (headline) · 152 · **202** (display) · 269 · **359** (mega).

**Пары в кадре.** Два текстовых уровня в одном кадре отличаются ≥×2. `resolve()` публикует `policy.type.framePairs` — все пары токенов с отношением ≥2 (display + body, headline + label). При ratio 1,333 headline стоит в кадре с label или UI-текстом, но не с body.

**Опорные диапазоны** (информативно, для шрифта уровня Inter; проверка идёт по полам и отношениям):

| Токен | 16:9 | 9:16 | 1:1 | 4:5 |
|---|---|---|---|---|
| mega | 300–680 | 360–480 | 280–400 | 300–440 |
| display | 170–235 | 160–220 | 140–200 | 150–210 |
| headline | 128–160 | 96–150 | 96–128 | 96–140 |
| subhead | 88–112 | 72–88 | 64–80 | 64–84 |
| body | 64–72 | 40–56 | 40–52 | 40–52 |
| label (CAPS) | 48–64 | 36–44 | 36–40 | 36–40 |
| caption | 56–64 | 52–60 | 48–56 | 48–56 |
| ui | 20–36 | 22–36 | 22–32 | 22–32 |
| code | 28–40 | 28–36 | 26–32 | 26–32 |

Значения в px при короткой стороне 1080 равны du (`HFT.du(value, format)` пересчитывает в px для любого формата).

**Внешняя шкала tokens_universal** [стартовая настройка]: display 160, headline 104, subhead 72, body 52, label 40, caption 44, detail 28 du; LH display 1,05 / headline 1,1 / body 1,35 / caption 1,25; трекинг display −0,03 em, headline −0,02 em, body и caption 0; заголовок ≤2 строки и ≤7 слов. Её body 52, label 40 и caption 44 ниже пола `feed16x9` (64 mixed / 48 CAPS / субтитр 48), поэтому годятся только для полноэкранных 9:16 / 1:1 / 4:5. Сама схема оговаривает, что display и detail не задают универсальных минимумов: финальный кадр смотрят на нужном носителе.

### Трекинг по размеру и регистру

Таблица собрана из токенов шкалы (у Higgsfield — таблица выше): при расхождении прав токен. В системе трекинг хранится в em (`trackingEm`): −4% = −0,04 em; в DTCG letterSpacing = em × fontSize в px.

| Размер | CAPS | Sentence case |
|---|---|---|
| ≥200 px | −4…−7% (mega −6%; СЛОВО −3% хром … −6% плоский) | −4…−8% (Inter-дисплей AV3 −6…−8% на 180–300) |
| 120–200 | −3…−6% (СЛОВО; claim −4%) | −3…−4% |
| 80–120 | −2…−4% (claim ≤110 −3%; подпись на футаже −2…−3%) | −2…−4% (keynote 88 −2%; statement −4%) |
| 48–80 | −2…−4% (split title 70–76 −4%; киккер −2%) | −1…−2% |
| 20–48 | +4…+8% (до +12% на 20 px) для мета-лейблов | 0…−2% (UI, субтитры); не ниже −2%: −6% на 43 px слипается (AV4) |

**⚠ Caveat.**
- Bringhurst 2.1.6 даёт **+5–10%** только для CAPS в наборном кегле; про отрицательный трекинг дисплея он не говорит.
- Формула динамических метрик Andersson (Inter v3) выходит на плато −2,2% от 48 px. Значения −1…−3% для SG CAPS на 120–200 px — экстраполяция ресерча [Э].
- Архив стоит на −2…−6% с медианой −4% (12/12) [А], поэтому следуем архиву.
- На тёмном белые CAPS «пухнут» [И irradiation illusion, Kremkow et al. 2014]. Если на 96–130 px буквы слипаются, ослабьте трекинг до −3% или шагните вес на ступень ниже.
- **Оптический размер.** Значения архива сняты так, как текст набран в Figma. Inter Display изначально плотнее Inter Text, поэтому при переносе трекинга с Inter на Inter Display ослабьте его примерно на 1 пункт (−4% → −3%) [Э].

**Единицы.** Трекинг всегда задаём в %, никогда в px; смешивание px и % — анти-паттерн в Launches. В After Effects трекинг в 1/1000 em: **−4% = −40**.

**Законы трекинга** (для любого шрифта) [А+И]:
- [обязательно] Мельче 48 px никогда не туже −0,02 em (−6% на 43 px слипается).
- [по умолчанию] Display / opsz-срез набирается плотнее, поэтому при переносе значения с текстового среза на дисплейный ослабляйте на 0,01 em.
- [по умолчанию] Светлые CAPS на тёмном на 96–130 px: если закрываются просветы (иррадиация), ослабьте на 0,01 em или шагните вес ниже.
- Проверка `validate()` V11: `trackingEm` внутри полосы таблицы для своего размера и регистра.

### Интерлиньяж, регистр, перенос

- **LH.**
  - CAPS-заголовки 88–100%; одна строка CAPS 80–90%.
  - Colour cards 96%; Inter Display-титулы 105–111%; двухстрочный keynote 109% (96 на 88).
  - Body 130–140%; промпт 140–155%; лог агента 120–165%; субтитры 120%.
  - Высота строки не должна резать глифы: ошибки 48/32 (FX) и 51/34 (AI).
  - В AE интерлиньяж задаётся в px: leading = кегль × LH.
- **Регистр.**
  - CAPS — имена, лейблы, claims, офферы, титулы: «ONE AD, MANY VERSIONS».
  - Sentence case с точкой — голос: «Say what changes.»
  - UI повторяет продукт.
  - CAPS-героя и sentence-героя в одном кадре не смешиваем.
- **Перенос.** Только по фразовым границам. Никогда не отрывать артикль или прилагательное от существительного.
- **Figma.** Vertical trim = «cap height to baseline», чтобы CAPS-заголовки оптически вставали на UI-карточки и чтобы стек титула мерился одинаково.

### Акцент: один приём на кадр, на 1–2 слова

[обязательно] Один приём выделения на кадр, на 1–2 слова [И Lupton; Treisman & Gelade] [А]. Разрешённые приёмы, в порядке частоты в доказательствах:
1. **Смена цвета или материала** ключевого слова или второй строки (12/12 Launches; 4/5 AV5).
   - Цвет действия (`accent.text`) — только если слово и есть действие или результат бренда. Пример (Higgsfield): лаймовая строка 2 в KL, AM: 2/12.
   - Иначе второй акцент фильма (`accent.secondaryText`) или материал. Пример (Higgsfield): magenta-ключ AS; строка 2 magenta / pink в AV4-E4; иридесцентное слово среди хромовых, P3; радиальные тинты в глифах, P4.
   - [обязательно] Если акцент в режиме fill-only (контраст с фоном <3:1, обычно на светлой сцене), вместо цветного текста — **блок-заливка** акцентом под текстом `fg.onAccent`. Пример (Higgsfield): на светлой сцене вместо лаймового текста — лаймовый блок под #131313-текстом.
2. **Контейнер.** Капсула, pill, plaque, selection box с 8 ручками 13 px, стикер со скосом −7,4°.
3. **Материал на шрифте.** Градиент, сатиновый металл, глянцевый inner shadow, радиальные тинты в глифах (в бренд-регистрах Higgsfield — также хром и металлик).
4. **Скачок масштаба** ≥2,5×: киккер против ключевого слова.
5. **Серый хвост.** Вторая клауза на 50% или `fg.muted` (Пример (Higgsfield): #8C8F86).
6. **Смена шрифта на одно слово**: `font.accent` или italic текстового шрифта для «скорости» (Пример (Higgsfield): Inter Bold Italic).
7. **Объект вместо слова**: лого, тайл, pill (Пример (Higgsfield): «Now with [Opus 4.8]»).

**Запрещено** [обязательно]:
- **Складывать «акцентный цвет + крупно + glow» на одном элементе.** Это раздувает бюджет акцента (Lupton: один сигнал на уровень) и поднимает общий уровень салиентности кадра. Если в кадре есть другие акцентные **или** другие крупные элементы, фокус перестаёт быть синглтоном по одному признаку, и его ищут медленнее [И Treisman & Gelade 1980; Duncan & Humphreys 1989].
- Менять вес посреди строки.
- Делать фальшивый italic или bold.
- Ставить больше 1–3 акцентных слов в кадре. Glow и бренд-глиф (у Higgsfield — sparkle ✦) расходуют тот же бюджет (подсчёт акцента — в главе «Цвет и свет»). Пример (Higgsfield): не больше 1–3 лаймовых слов.

### OpenType

- `tnum` — на всех меняющихся числах. Иначе счётчик дрожит примерно на ¼ em: «1» = 0,39 em, «0» = 0,65 em.
- `case` — на CAPS с пунктуацией: «KLING 4.0», «00:12».
- Inter: `zero` + `ss02` в промптовом UI. `cv11` (однопетлевое a) — опционально, один раз на фильм.
- Inter opsz 32 (Display) — для всего ≥32 px.
- **⚠ After Effects.** Текстовый движок AE может не показывать стилистические наборы и character variants, и тогда фичи, выставленные в Figma, молча пропадают при переносе живого текста (проверьте свою версию AE). Правило: `ss02`, `cv11`, `zero` — только на обведённых копиях или там, где текст не анимируется живым. Если `tnum` в AE не применился, счётчик собирают из цифр в боксах фиксированной ширины или моноширинным шрифтом (Space Mono).

[обязательно] Меняющиеся числа — `type.number` / `type.code` с `tnum` и `case` в `$extensions.features`. Бренд-глифы (звёзды, знаки) — векторные инстансы, никогда не набранные символы.

## Пол читаемости и время чтения

### Пол читаемости: высота буквы, а не кегль

[обязательно] Читаемость меряется **высотой буквы в px кадра**, а не кеглем: x-height для mixed case, высота капители для CAPS (ARCHITECTURE §3.8, `core.legibility`) [И Legge & Bigelow 2011; Bababekova 2011; BBC] [А] [Э]. Три уровня:
- **floor** — ниже ошибка (`validate()` V06, error);
- **target** — домашний must-read; ниже предупреждение;
- **comfort** = 2 × floor — для ключевого сообщения кадра.

**Формула.** fontSizePx = round(letterHeightPx / r_font), не ниже 20; r_font = xHeight/em (mixed) или capHeight/em (CAPS) **именно этого шрифта**. Угол → px: letterHeightPx = 2 · d · tan(θ/2) / mmPerFramePx. Допуск проверки 2%. Абсолютный пол — **20 px при короткой стороне 1080** (V07); меньше — текстура без смысла.

Роли: `type.body`, `type.headline`, `type.display` меряются по floorX (mixed) или floorCap (CAPS); `type.label` (CAPS со смыслом) — по floorCap; `type.caption` — по правилам субтитров; `type.ui` — только абсолютный пол; вторичный текст — secondaryX.

| Контекст (`policy.contexts`) | Формат | d, мм | Высота буквы, px: floor x / floor cap / target x / secondary x / comfort x | Угол, °: floor / target / comfort | Inter, px: floor mixed / floor CAPS / target mixed / secondary / comfort mixed |
|---|---|---|---|---|---|
| `feed16x9`: 16:9 в портретной ленте (×0,2). **Решающий случай для 16:9-мастера в соцсети** | 16:9 | 340 | 35 / 35 / 35 / 20 / 70 | 0,20 / 0,20 / 0,40 | **64 / 48 / 64 / 37 / 128** (CAPS comfort 96) |
| `full16x9`: телефон горизонтально, весь экран | 16:9 | 340 | 25,5 / 25,5 / 25,5 / 16,4 / 51 | 0,33 / 0,33 / 0,66 | **47 / 35 / 47 / 30 / 93** |
| `full9x16`: Reels / TikTok / Shorts | 9:16 | 340 | 22 / 26 / 26,2 / 17,5 / 44 | 0,25 / 0,29 / 0,49 | **40 / 36 / 48 / 32 / 81**; заголовок 96–150; субтитр ≥52 |
| `feed1x1` / `feed4x5`: на всю ширину ленты | 1:1, 4:5 | 340 | 22 / 26 / 26,2 / 17,5 / 44 | 0,25 / 0,29 / 0,49 | **40 / 36 / 48 / 32 / 81** |

**Примеры для `feed16x9`:** Inter mixed 64 px; Inter CAPS 48 px; Space Grotesk CAPS (cap 0,700) 50 px; Playfair mixed (x-height 0,414) **85 px**; Playfair CAPS (cap 0,571) 61 px. Метрики OS/2 — в `core.json → legibility.referenceFaces` (Inter, Space Grotesk, Geist, Archivo, Bricolage Grotesque, Plus Jakarta Sans, Mona Sans, Unbounded, Sofia Sans Extra Condensed, Fraunces, Playfair, Martian Mono, Doto).

**Законы.**
- [обязательно] Деливерабл проходит **самый строгий контекст, куда он уходит**: 16:9-мастер для соцсетей проходит `feed16x9` [Э].
- [обязательно] UI-текст может быть ниже пола, только если наезд камеры доводит его до пола в утверждённом B-rest кадре. Копи не влезает — делим на кадры, кегль не уменьшаем [А].
- [обязательно] Цветной текст ≥40 px. Текст, чья яркость отличается от фона на ΔY′ <60 (8 бит), — ≥64 px Bold, обводки ≥4 px: 4:2:0 размывает края, которые держатся только на цветности [С BT.709 / 4:2:0] [Э]. Проверка V17.

**Пример расчёта (Inter, соцсети)** — исходная таблица Библии:

| Сценарий просмотра | Масштаб | Обязательно читать | Вторичное |
|---|---|---|---|
| 16:9 на весь экран телефона (landscape) | ≈2,75 px/pt | ≥47 px | ≥30 px |
| 16:9 в портретной ленте (X, LinkedIn) | ×0,2 (≈4,9 px/pt) | **≥54–64 px** mixed case / ≥48 CAPS | ≥36 px, иначе текстура |
| 9:16 на весь экран | ≈2,75 px/pt | ≥40–48 px | ≥30–32 px |

Основа: порог беглого чтения по x-height ≈0,2° [И Legge & Bigelow 2011], телефон на 32–36 см [И Bababekova 2011], BBC (строка 7–8% высоты кадра) [С].

**Цель комфорта, а не только пол.** Ключевое сообщение кадра в ленте 16:9 — около 0,4° угла: **≈128 px mixed / 96 px CAPS** [Э по typography P1]. Поддерживающий текст поверх генерации — до ~85 px.

**Светлое на тёмном читается хуже** на мелких кеглях и в тёмном окружении [И Piepenbrock et al. 2014; Dobres et al. 2017 — по пересказу отчёта, не перепроверено]. Для тёмных кадров минимумы выше [Э]: текст, который на экране <1,5 с, ≥40 px; чипы ≥24 px; заголовки 16:9 для соцсетей ≥120 px.

**Практика:** всё, что несёт смысл бита, ≥48 px (CAPS) или ≥64 px (mixed). Мета 22–28 px — структура и фактура, а не сообщение.

### Сколько слов в кадре

- **Заголовок** ≤2 строки по 2–4 слова (≤5–7 слов); 16:9: ≤20 CAPS-знаков на строку на 152 px; 9:16: ≤12–14 знаков на 96 px.
- **Всего обязательного текста** в кадре ≤12–15 слов [Э]. Если копи не влезает, разбиваем на кадры, а не уменьшаем кегль.
- **Видимый промпт**: ≤30–40 знаков для prompt-hero, ≤60 для prompt-фактуры (архетип «Prompt hero»). Печать ≤20 знаков/с; если промпт читается дословно — 15 знаков/с.
- [обязательно] Заголовок — 2–7 слов на ≤2 строках. Дизайн-текст — ключевые слова, а не транскрипт VO; субтитры — отдельный слой доступности [И Mayer & Johnson 2008].
- [обязательно] **Ёмкость окна бита:** не больше **floor((dur − 0,6 − 0,5) / 0,35)** обязательных слов; 0, если dur − 0,6 < 1,0 с (0,6 с — сборка, 0,5 с — найти текст после склейки) [Э].
- [обязательно] Символов в строке: maxChars = рабочая ширина / (кегль × средняя ширина капители в em). Измерено: Space Grotesk Bold 0,551, Inter Display Bold 0,584, Barlow Condensed 0,421, Special Gothic Expanded One 0,72.

### Время чтения: одна формула

**Итоговое правило** [обязательно] (`core.reading`, `HFT.readTime(text, {script, k, conservative})`):

> **hold_s = max(T_min; (0,35 × слова + 0,5) × k)**, кадры = ceil(hold_s × fps), и никогда меньше 20 кадров.

- **T_min = 1,0 с** [Э] по умолчанию; **1,2 с** в консервативном режиме [стартовая настройка] — для аудитории, читающей не на родном языке, эфира и обучающих роликов.
- **k** — множитель сложности, k ≥ 1 [стартовая настройка: 1,0]. Текст поверх движущейся генерации без заморозки или скрима: k = 1,3 [И Vital et al. 2022] [Э]. Плотные числа, имена и термины: k подбирается просмотром и пишется в паспорт.
- 0,35 с на слово ≈ Brysbaert 238 wpm с запасом; BBC 0,3 с/слово; +0,5 с — найти текст после склейки [Э].
- Сборка (≤0,6 с) и разборка идут **сверх** hold.
- Примеры (k = 1): «CINEMA STUDIO» (2 слова) ≈ 1,2 с; 4 слова ≈ 1,9 с; 10 слов ≈ 4,0 с.
- **Абсолютный пол:** любой текст на экране ≥20 кадров; одно событие субтитра ≤7 с [С Netflix TTSG].
- Округление: время удержания и минимум чтения — `ceil` (`HFT.ms2f(ms, fps, {hold: true})`); границы битов округляются кумулятивно по общему числу кадров, без щелей и нахлёстов (глава о тайминге).

**Почему одна формула, а не две.** Внешняя схема даёт max(1200, (500 + 300 × слова) × k) мс [стартовая настройка]. При ≥3 словах наша формула строже (4 слова: 1,9 с против 1,7 с; 10 слов: 4,0 против 3,5 с), поэтому от внешней берём только пол 1,2 с как консервативный режим и множитель k.

**Письмо без пробелов между словами и длинные слова** (японский, китайский, тайский, корейский; немецкие композиты) [Э]:

> **hold_s = max(T_min; (знаки / cpsDesign + 0,5) × k)**, где cpsDesign = 0,75 × максимум субтитров для языка.

| Письмо | Максимум субтитров, знаков/с [С Netflix TTSG] | cpsDesign |
|---|---|---|
| Латиница / английский | 20 | 15 |
| Арабский | 20 | 15 |
| Корейский | 12 | 9 |
| Китайский упрощённый | 9 | 6,75 |
| Японский | 4 | 3 |
| Не указанные (в т. ч. тайский) | 17 | 12,75 |

Формула по словам не подходит для CJK и тайского: `HFT.readTime` переключается на знаки по `script`.

**Печать текста (type-on)** [Э]:
- Скорость ≤20 знаков/с; если промпт читается дословно — 15 знаков/с (совпадает со стартовой настройкой внешней схемы); ≤1 знака на кадр при 24 fps.
- Время набора засчитывается как чтение, только если зритель успевает следить (≤15–20 знаков/с). После последнего знака держать ≥0,5 с [Э]; в консервативном режиме 0,6 с [стартовая настройка].
- [исключение] Нечитаемое появление (scramble, глитч, слишком быстрый набор) временем чтения не считается: hold отсчитывается от момента, когда текст стал читаемым.
- [исключение] Быстрый декоративный текст (роль `texture`, буквы как фактура) формулой не растягивается: он не обязан читаться, но обязательный смысл отделён от текстуры.

[обязательно] Оценка по формуле не заменяет просмотр: итог проверяется на целевом языке и носителе.

**Текст поверх движения, дублирование VO, кинетика.**
- **Текст поверх движущейся генерации читается медленнее** [И Vital et al. 2022]. На время hold плейт под текстом замораживаем или замедляем, либо добавляем скрим; иначе hold +30% [Э].
- **Дублирование VO — два слоя.**
  1. Дизайн-текст кадра (заголовок, claim) не повторяет VO дословно: ключевые слова, а не транскрипт [И Mayer & Johnson 2008, redundancy].
  2. **Субтитры VO** — отдельный слой доступности для просмотра без звука: всегда есть, одна позиция, вне фокус-зоны (см. «Субтитры и VO-pill»). Redundancy-принцип выведен на уроках со звуком, а соцвидео часто стартует без звука, поэтому субтитры им не запрещены.
- **Кинетика текста.** Анимированные подписи нравятся больше, но понимание не улучшают [И Rashid et al. 2008]. Проектируем читаемый **устоявшийся** кадр; имена продуктов и текст промпта не деформируем.

### Субтитры и VO-pill (просмотр без звука)

**Зачем.** В ленте видео часто стартует без звука [С Apple App Preview: превью автоплеятся без звука]. Для аудио-продукта (lipsync, голос) доказательство — это звук, и без подписей зритель видит просто говорящего человека.

| Параметр | 16:9 | 9:16 |
|---|---|---|
| Когда | на каждом озвученном бите и на каждом бите, где доказательство — звук | то же |
| Слот | фиксированный на весь фильм: центр по x960, бокс y≈880–980, нижний край ≤y1000 | y≈1150–1250, внутри x72–888 |
| Кегль | Inter SemiBold ≥48 px (mixed 56–64 для ленты) или SG Bold CAPS ≥48 | ≥52 px |
| Строки | ≤2 строки, ≤32 знака в строке, перенос по фразам | ≤2 × ≤22–26 знаков |
| Подложка | pill чёрный 60%, cr = ½ высоты, паддинг 24/14; или скрим 40–60% | то же |
| Активное слово | опционально лаймом; тогда это эхо лайма в кадре, других эхо нет | то же |
| Тайминг | ≤20 знаков/с; каждый субтитр ≥20 кадров [С Netflix TTSG] | то же |
| VO-pill с аватаром | аватар 72 px с лаймовым кольцом 3 px (AI kit) — это тот же контейнер | — |

**Решения и исключения.**
- **Позиция одна на фильм.** Пузырь, который прыгает по углам, — анти-паттерн AI (нижнее поле то 18, то 36 px). Субтитры рядом с контентом держат взгляд ближе к просмотру без субтитров [И Brown et al. 2015, BBC R&D dynamic subtitles], но дом выбирает фиксированный слот ради единства. Единственное осознанное исключение — архетип «Sound-on proof»: субтитр под карточкой результата.
- **Аудио-продукты** — исключение из правила «не дублировать VO»: субтитры обязательны, подсветка активного слова — часть доказательства.
- **Деливерабл:** вшитые субтитры + файл SRT (и VTT) на каждый язык (см. «Выдача по площадкам»).
- Старый токен `vo.subtitle` SG Bold 38 [А AI] ниже пола ленты: поднят до 48.

**Субтитры во всех форматах** [С Netflix TTSG, BBC] [А] [Э] (`type.caption`, ARCHITECTURE §3.17.3):

| Формат | Бокс по y | Минимальный кегль | Строки | Знаков в строке |
|---|---|---|---|---|
| 16:9 | 880–980 (нижний край ≤1000) | 48 CAPS / 56–64 mixed | ≤2 | ≤32 |
| 9:16 | 1150–1250, x 72–888 | 52 | ≤2 | ≤22–26 |
| 1:1 | 860–960 | 48 | ≤2 | ≤24–28 |
| 4:5 | 1080–1180 | 48 | ≤2 | ≤24–28 |

- [обязательно] Подложка — pill цвета фона (`bg.overlay`) 60%, радиус = ½ высоты, паддинг 24/14, или скрим 40–60%. Пример (Higgsfield): pill чёрный 60%.
- [по умолчанию] Подсветка активного слова — `accent.action`; она считается эхом акцента кадра. Пример (Higgsfield): лайм.
- [обязательно] Каждый бит читается без звука: ленты автоплеят без звука [С].
- Скорость субтитров по языкам — таблица cps выше; ≤20 знаков/с для латиницы.

## Локализация и системы письма

### Шрифт обязан покрывать каждое письмо

- [обязательно] Каждый `typeVoice` объявляет шрифт для каждого письма (ISO 15924): Latn, Cyrl, Grek, Jpan, Kore, Hans, Hant, Arab, Deva → токены `font.fallback.{Cyrl, Grek, Jpan, Kore, Hans, Hant, Arab, Deva}` и `brandConfig.fonts.fallbackByScript`. Список писем фильма — `policy.type.scripts`.
- [обязательно] Никогда не набирать письмо шрифтом, в котором его нет; проверять по файлу шрифта, а не по превью (V09). Многие display-шрифты без кириллицы.
- [по умолчанию] Fallback: Inter для Cyrl и Grek; Noto Sans JP / KR / SC / TC / Arabic / Devanagari для остальных.
- [обязательно] **Подгонка по капители:** fallbackSize = size × capHeight(основной) / capHeight(fallback). Пример: Space Grotesk → Inter = × 0,700 / 0,728 = 0,96. Для CJK, арабского и деванагари — подгонка по высоте капители латиницы в той же строке.
- [обязательно] Пол читаемости считается по метрикам **реального** fallback-шрифта (у Noto Sans JP и Noto Sans Arabic другие x-height, чем у латинского шрифта).

**Пример (Higgsfield): нелатинские шрифты.**
- Space Grotesk в Google Fonts покрывает только latin, latin-ext и vietnamese: кириллицы нет (проверено по файлу шрифта), CJK, арабского и деванагари тоже нет. **SG никогда не используется для нелатинского текста.**
- Кириллица и греческий → Inter / Inter Display тем же весом. Чтобы капитель совпала, кегль Inter = кегль SG × 0,96 (капитель SG 0,70 em, Inter 0,727 em).
- Японский, корейский, китайский, арабский, деванагари → Noto Sans JP / KR / SC, Noto Sans Arabic, Noto Sans Devanagari, с подгонкой по высоте капители латиницы в той же строке.
- Это касается галерей «любой язык», субтитров и локализованных версий.

### Справа налево (RTL)

- [обязательно] `brief.textDirection = rtl`: зеркалим порядок чтения, раскладку текста и UI-клонов (стрелки «вперёд», прогресс, порядок чипов, ведущий край).
- [обязательно] **Никогда не зеркалим механически** логотипы, графики, оси времени, видеоплейты, лица и предметы, медиа-контролы с физическим смыслом, цифры внутри чисел.
- [обязательно] Редакционная ось = **ведущий край** (leading edge): в LTR слева, в RTL справа. Отступы, якоря lower third и ось `leftAxis` задаются как leading / trailing, а не left / right.
- [по умолчанию] Направление движения «вперёд» следует направлению чтения (в RTL справа налево); направление камеры и физики сцены не меняем.
- [обязательно] Смешанные строки (RTL-текст + латинское имя продукта или число) проверяем на правильный bidi-порядок в финальном кадре.

### После перевода

- [обязательно] Перераскладка и пересчёт времени после каждого перевода: строки, переносы по фразам, `HFT.readTime` для нового языка и письма, ёмкость окна бита.
- [обязательно] **Никогда не ужимать обязательный текст под старую рамку.** Не влезает — расширяем бокс, сокращаем копи с автором, делим на кадры или удлиняем бит.
- [обязательно] Субтитры и вшитый текст — свой файл SRT / VTT на каждый язык; CPS по таблице языка.
- [по умолчанию] Акцентный шрифт без нужного письма заменяется весом и материалом основного шрифта того же письма, а не другим display-шрифтом.

## Цвет и свет

Цвет в системе — это **роли**, а не hex. Палитру строит `HFT.derive({seed, mood, scheme})` в OKLCH из 1–2 сидов бренда (DERIVE.md) или берёт ось `palette` стиля; бренд переопределяет роли через `brandConfig.colorOverrides {light, dark}` и фиксирует смыслы в `fixedColorMeanings`. После любой замены `HFT.validate(theme)` перепроверяет все пары (V01–V05, V15–V19, V21).

### Бюджет площади и подсчёт акцента

- [обязательно] **Нейтрали занимают 85–95% кадра**; нижнего предела для акцента нет: кадр может быть без акцента [А].
- [по умолчанию] **Доля акцента зависит от его салиентности** (ARCHITECTURE §3.16.1) [А+И Itten; High 2023] [Э]: weight = √(\|Lc(action, bg)\| / 96) × (0,75 + 0,25 × √(C / 0,222)), ×1,2 при H ∈ [320°, 40°] или [250°, 300°] (эффект Гельмгольца — Кольрауша), ограничить 0,5–1,6; ext = clamp(1 / weight; 0,6; 1,2). targetPct = moodTarget × ext; maxPct = moodMax × ext.
- [обязательно] **Жёсткий потолок 18%**; fill-only на светлом фоне ≤8% (V05). Glow-пулы не считаются.

| Настроение (`mood`) | target / max, % | объекты + эхо | второй акцент max, % |
|---|---|---|---|
| calm | 3 / 6 | 1 + 0 | 0 |
| luxury | 2 / 4 | 1 + 0 | 0 |
| energetic | 7 / 12 | 1 + 2 | 5 |
| playful | 8 / 14 | 2 + 1 | 6 |
| technical | 4 / 8 | 1 + 1 | 3 |
| editorial | 3 / 6 | 1 + 1 | 0 |
| одиночный неоновый акцент на почти чёрном (weight 1,0) | 4 / 8 | 1 + 1 | — (это норма архива Higgsfield) |

- [обязательно] **Флуд акцентом на весь кадр:** energetic и playful — ≤1 раза на 15 с (бамперы); другие настроения — только на end card.
- [обязательно] **Подсчёт.** Объект — связный акцентный элемент вместе со своим свечением; набор одинаковых чипов — один объект; эхо — меньший элемент с тем же смыслом. Объекты и эхо — по настроению (никогда больше 2 + 2), **фокус всё равно один**. Не считаются: каретка при наборе, акцентные токены внутри UI-текста, акцент внутри сгенерированного медиа [А+И Treisman & Gelade; Itti & Koch].
- [обязательно] **Второй акцент:** ≤1 на фильм, один смысл, ≥90° OKLCH-тона от основного, ≤6% (≤15%, если это цвет героини-фичи); никогда на логотипе, главном CTA и бренд-глифе. Статусные цвета держат ≥35° от тона акцента: один цвет — один смысл [Э].
- [по умолчанию] Magenta, синие и красные акценты выглядят ярче своей L, поэтому им на 20–30% меньше площади, чем cyan или жёлто-зелёному той же L [И High 2023; Corney 2009] [Э].

**Как считать лайм в кадре** (заполнение общего правила подсчёта) (правило «один объект + одно эхо»):
1. **Объект** — связный лаймовый элемент вместе со своим свечением: glow, привязанный к эмиттеру, считается вместе с ним.
2. **Набор одинаковых чипов одного стиля в одной группе** = один объект.
3. **Эхо** — второй, меньший элемент с тем же смыслом: строка 2 заголовка, кнопка play, прогресс плеера, активное слово субтитра, кластер sparkle на lockup.
4. **Не считаются:** каретка во время набора; @mentions и лаймовые токены внутри текста промпта (это UI, а не акцент); лайм внутри самой генерации (лаймовые наушники, гидрокостюм).
5. **Пример, AI 4.8:** героиня с glow = объект; набор delta-pills = второй объект, поэтому квалификатор числа делаем белым или оставляем один delta-pill на героине.

**Семантика вторых цветов, пример на фильм.**
- AM: лайм = keep / new / brand; magenta = change.
- KL: cyan / лайм / magenta = past / present / future.
- AI: лайм = взаимодействие; magenta = лайки.
- AV4-E4: лайм = финал и победа; magenta = главный цвет акцента и метрик.

**Второй цвет ≥90° по OKLCH-тону от лайма** [Э]: лайм H≈122; cyan 226, magenta 5, pink 14 и lilac 320 проходят. Второго цвета нет на логотипе, CTA и ✦ (кроме пары sparkle magenta + лайм в орнамент-ките). Один смысл на весь фильм.

### Тёмные и светлые сцены

**Законы** (ARCHITECTURE §3.16.6–3.16.8) [А+И]:
- [обязательно] Тёмная сцена — для зрелища, светлая — для чтения [И Piepenbrock 2013–14].
- [обязательно] На светлом фоне акцент с контрастом <3:1 к фону — **только заливка**: никогда не текст и не обводка тоньше 12 px. Аддитивный glow клипуется — вместо него цветная мягкая тень (y 12, blur 40, 25–35%). Карточке на бумаге нужна тень ink 6–14%, blur 48–96, y 16–32 + обводка 1 px (белая карточка без тени — 1,11:1).
- [по умолчанию] Серые рядом с большой акцентной площадью получают хрому 0,006–0,008 в тоне акцента (одновременный контраст) [И Albers] [Э].

**Пример (Higgsfield):**

- **Тёмная — для зрелища**: герой-генерация, один заголовок, светящиеся акценты. **Светлая — для чтения**: плотный UI, промпты, многострочный текст. Тёмный текст на светлом лучше для мелкого текста [И Piepenbrock et al. 2013–2014].
- **Пропорции на тёмном**: ink и карточки 80–90%; генерация столько, сколько нужно; лайм ≤8%; второй акцент ≤3–5%; glow-пулы не считаются.
- **Пропорции на светлом**: фон и нейтрали 90–97%; лайм только как заливка или чип ≤5–8%; corner-блумы magenta или сиреневого допустимы.
- **На светлой сцене лайм никогда не текст и не тонкая линия** (тонкая = любая обводка <12 px): лаймовая капсула заливается целиком, текст #131313. Тёмный UI-объект на светлой сцене работает как «драгоценность» (PS-панель 714×971 cr31–39 с полями 55 px сверху и снизу).
- **Смена полярности** — только на границе акта, на доле, через вайп или вспышку. Не посреди шота.
- **Последовательный контраст.** После склейки тёмное → светлое первые кадры бумага кажется ярче, а лайм тусклее. Ключевой лаймовый элемент вводим через ~0,3 с после склейки [И Albers, Chevreul — эффект; 0,3 с — Э].
- **Серый рядом с большим лаймом** чуть сдвигаем к лайму: #A0A29D вместо #A1A1A1, иначе он отдаёт фиолетовым.

### Свет: glow, bloom и градиенты

**Законы света** (ARCHITECTURE §3.16.10, §3.16.5) [И Spencer 1995; Jimenez 2014; Ottosson 2020] [Э]:
- [обязательно] Одна модель света на фильм (`light.model`: flat | soft | rim | emissive); ключевой свет сверху или сверху слева (`light.keyAzimuth` −45…0°).
- [по умолчанию] В кадре один источник света + один тактильный объект, кроме `material = flat` и полноэкранного медиа. Правило тактильного объекта — урок Higgsfield «слишком плоско» [А], сделанный условным.
- [обязательно] Эмиттер = горячее ядро (`accent.core`, L 0,98) + многомасштабный ореол: blur 4 / 12 / 32 / 96 / 240, gain 0,8 / 0,5 / 0,3 / 0,18 / 0,10. В 200 px от источника фон ≤ OKLCH L 0,30. В linear-light композициях gain свечения режем в 2–3 раза.
- [обязательно] Рампы и градиенты строим в OKLCH. Градиент от тона к тону допустим, только если тон его OKLCH-середины в пределах 30° от тона палитры или хрома середины <0,05; иначе разводим тона пространственно через нейтраль (например, лайм → magenta проходит через оранжевый).
- Токены: `glow.pool` (анти-бандинговый пул: центр OKLCH(L_bg + 0,075, тон акцента, C ≤0,05) → `bg.base` → `bg.sunken` на r ≈900 px, ≥20 кодовых значений; на светлой схеме — pearl-дымка с тинтом сида), `atmos.primary/secondary`, `glow.action`, `glow.selected`, `glow.hero`.

**Модель света AV5** (3/5: P1, P3, P4): каждый выделенный объект получает три слоя.
1. **Rim-light**: радиальная белая обводка w2–4 (белый → прозрачный → белый).
2. **Верхний внутренний свет**: `IS(0, 8, 20, 0, #FFF, 15%)` + `IS(0, −6, 4, 0, #FFF, 30%)`.
3. **Внешний цветной glow**: персик #F09570 blur 30–40, или лаймовый bloom #ADF537 50% blur 250, или G17.

P2 и P5 остаются плоскими. Модель выбирается в паспорте и не смешивается с G1-пулами.

**Linear vs gamma.** Одни и те же 8% лайма дают #222613 при обычном смешивании и #445314 в linear-light Add [И/Э отчёт по цвету]. Figma показывает гамма-смешивание, поэтому в 32-bpc linear-проекте AE gain свечений режем в 2–3 раза и сверяем с утверждённым кадром.

**Яркость: лайм против magenta.** Яркость лайма — это просто его светлота; эффект Гельмгольца — Кольрауша в жёлто-зелёном слаб. Magenta выглядит ярче своих чисел [И High et al. 2023; Corney et al. 2009]. Поэтому magenta нужно примерно на 20–30% меньше площади, чем cyan, чтобы ощущаться равной [Э]; равный OKLCH L при высокой насыщенности не значит равную воспринимаемую яркость.

**Вибрирующая граница.** Тонкие magenta-обводки не касаются cyan-заливок: разводим их ≥8 px ink или бумаги [И Albers; число Э].

**Свет на светлой сцене.** Аддитивный glow на светлом фоне клипуется, поэтому не работает. Вместо него:
- цветная мягкая тень под лаймовыми чипами: `DS(0, 12, 40, 0, #B8E103, 25–35%)`;
- карточки: ink 6–14%, blur 48–96, y16–32 + 1 px #E4E4E4. Белая карточка на бумаге без тени — это всего 1,11:1.

**Градиенты.**
- Строим в OKLCH.
- **Никогда лайм → magenta напрямую**: в середине оранжевый #DF8A44, off-brand. Разводим их пространственно, через ink, или используем иридесцент на 10%, как pearl plaque.
- Cyan → magenta через OKLCH даёт чистую фиалку #A985FF; sRGB даёт грязь.
- Лайм → жёлтый или зелёный градиенты читаются «токсично». Исключение — top-light #FFFF14 на кнопке.

### Зерно, бандинг и компрессия

**Законы** (ARCHITECTURE §3.16.9, §3.16.12) [С BT.709] [И Tandon 2021] [А] [Э]:
- [обязательно] Пол значимого контента BT.709 — Y′ 32. Всё, что должно отличаться от фона, — ΔY′ ≥7.
- [обязательно] Большие градиенты покрывают ≥20 кодовых значений или дизерятся (σ 1–1,5%, 1–2 px) (V16).
- [обязательно] Цветные обводки ≥3–4 px; акцентные ≥2 px.
- [обязательно] Зерно никогда не на UI; ≤5% на светлых сценах; допустимо внутри плейтов; halftone и dot-screen — только как орнамент-кит фильма. 1 px хейрлайны и мелкие паттерны на **движущихся** элементах мерцают — ≥2 px.
- Внешняя стартовая настройка зерна `grainOpacity` 0,02 [стартовая настройка] укладывается в эти пределы; качество не определяется наличием зерна, металла или стекла.

**Пример (Higgsfield) и детали:**

- **Зерно** [А]: Launches 2/12 (U8 — 5% зерна на светлой сцене; один рекламный still AS); AV3 0/11; AV4 только внутри кино-плейтов; AV2 6/18 (шум 4% в стекле, 8% на обложках, до 40–60% на интро); AV5: шум 15% soft-light и halftone / dotted-screen текстуры в 3/5.
  - Правило: на светлой сцене допустимо зерно сцены ≤5%; на UI зерна нет; halftone и dotted screen — только как элемент орнамент-кита (см. «Орнамент-киты»); плёночное зерно живёт внутри плейтов.
  - ⚠ Ресерч рекомендует дизер на **экспорте** в AE: монохромный шум σ≈1–1,5% (2–4 кода, 1–2 px) только на больших тёмных градиентах [Э].
- Работаем в 16/32 bpc. Тёмный градиент должен покрывать ≥20 кодовых значений: #131313 → #1B1B1B — это всего 8 значений, и на 1920 px дадут полосы шириной ~240 px. PNG из Figma 8-битный, поэтому большие градиенты и свечения пересобираются в AE, а не экспортируются (см. «Передача в After Effects»).
- **4:2:0.** Форма цветного текста и линий держится на **яркостном** контрасте:
  - цветной текст ≥40 px;
  - цветные обводки ≥3–4 px;
  - лаймовые обводки ≥2 px (1 px после сглаживания становится оливой #728815);
  - **magenta-хейрлайны и magenta-текст <64 px на тёмном запрещены** (Δ luma 47).
- **Rec.709.** #131313 = пол значимого контента (Y′ 32). Всё, что должно отличаться от фона, ≥#1B1B1B. Экспорт H.264 High, 4:2:0, теги BT.709. Мастер — ProRes 4444. Итог проверяем через реальную загрузку в Instagram или X (см. «QA моушна»).
- **Не мельчить**: 1 px хейрлайны на **движущихся** элементах и мелкие повторяющиеся паттерны мерцают при движении и сжатии. Хейрлайны 5–10% на статичном хроме допустимы.

Правило вспышек — в главе «Контраст и доступность».

## Контраст и доступность

### Две шкалы: WCAG 2.x и APCA

- [обязательно] Проверяем по WCAG 2.x **и** APCA; **побеждает более строгий вердикт** [С WCAG 2.2 1.4.3 / 1.4.11; APCA Bronze, черновик] [Э].
- [обязательно] WCAG: относительная яркость sRGB, контраст = (L_max + 0,05) / (L_min + 0,05). **Полупрозрачные слои сначала сводим** в итоговый цвет на реальном фоне, потом меряем.
- [обязательно] Ниже пола — ошибка; между полом и целью — предупреждение, на основной поверхности роли (V01).
- [по умолчанию] Держим запас над минимумами: компрессия и экраны телефонов снижают контраст.
- [обязательно] Текст поверх изображения: меряем по **худшему пикселю** под глифами; ниже цели — скрим цвета фона (`bg.overlay`) 40–70%.
- [по умолчанию] Иерархия видна: \|Lc(`fg.primary`)\| − \|Lc(`fg.muted`)\| ≥20 (V21).

**Набор пар `HFT.validate()`** (структура из tokens_universal `quality.contrast`; пороги внешней схемы — внутренние цели, а не сертификат [стартовая настройка]):
- **textPairs**, цель ≥4,5:1: text / background, text / surface, text / surfaceRaised, textMuted / background, textMuted / surface, onAccent / accent, onPositive / positive, onWarning / warning, onNegative / negative → в наших ролях `fg.primary` / `bg.base`, `fg.primary` / `bg.raised`, `fg.muted` / `bg.base`, `fg.muted` / `bg.raised`, `fg.onAccent` / `accent.action`, `fg.on*` / `state.*`.
- **essentialGraphicPairs**, ≥3:1: borderEssential / background, borderEssential / surface → `line.essential` / `bg.base`, `line.essential` / `bg.raised`.
- Все пары проверяются для каждого пресета и каждой производной темы, в обеих схемах.
- На видео дополнительно учитывать движение, реальный размер просмотра и меняющийся фон; для интерфейсов действуют требования их среды.

| Вопрос | Да → | Нет → |
|---|---|---|
| Пропадёт ли смысл, если линию убрать (граница поля ввода, контур выбранной карточки, ось графика, линия «до/после», граница кнопки без заливки)? | `line.essential`, ≥3:1 | дальше |
| Это фокус или выбор? | `line.focus` (≥3:1, иначе `accent.edge`) | дальше |
| Линия только организует (край карточки на контрастной заливке, разделитель, сетка-фактура)? | `line.hairline` 1–2 px, ≈1,25:1 composite | — |

- [обязательно] На движущихся элементах любая линия ≥2 px; цветная линия, держащаяся только на цветности, ≥3–4 px (4:2:0).
- [обязательно] Заливка карточки, неотличимая от фона (ΔY′ <7), требует значимого края или тени (V15).

### Цвет — не единственный носитель смысла

- [обязательно] Смысл никогда не кодируется только тоном: статусный цвет дополняется формой, подписью, позицией или разницей OKLCH L ≥0,15 (V19) [Э].
- [обязательно] Пары positive / negative и «до / после» различимы в ч/б (проверка: десатурировать кадр).
- [по умолчанию] Проверить кадр симуляцией дейтеранопии и протанопии; красный / зелёный без подписи не используем.

### Вспышки и вестибулярная безопасность

- [обязательно] **≤3 вспышки в любую 1 с.** Вспышка — пара противоположных изменений относительной яркости ≥10%, где более тёмное состояние <0,80 [С WCAG 2.3.1]. Если чаще — площадь мигания ≤25% любого 10° поля зрения: WCAG даёт 341×256 при 1024×768, эквиваленты **640×360 (16:9), 360×640 (9:16), 360×360 (1:1), 360×450 (4:5)**; для эфира ≤25% экрана [С Ofcom, ITU-R BT.1702]. Отдельно — никаких насыщенных красных вспышек.
- [обязательно] Акцентный хит длится ≥4 кадров (24 / 25 fps), 5 (30 fps), 10 (60 fps) [Э]; мерцание (twinkle) ≤3 Гц. Проверка V18: частота вспышек, слайсов и мерцаний ≤3 в секунду.
- [обязательно] **Финальный рендер** прогоняется через PSE-анализатор (Harding FPA или PEAT). Числа в конфиге безопасность не доказывают: проверяется только итоговое видео в условиях размещения.
- [по умолчанию] Большие зумы (>2×) и быстрый боковой параллакс — самые рискованные вестибулярные движения: плавные кривые, ≤1 на бит, никогда в цикле [Э].
- [обязательно] Интерактивные и веб-циклы уважают `prefers-reduced-motion`: показываем B-rest кадр, убираем параллакс и движения камеры [С].
- Громкость (для полноты): соцсети −14 LUFS integrated, true peak ≤ −1 dBTP; эфир −23 LUFS, EBU R128 [С / Э]. Подробно — в модуле `audio`.

**Пример (Higgsfield), исходная формулировка Библии:**
- **Вспышки.** ≤3 вспышки (пар противоположных изменений яркости ≥10%) в любую 1 с [С WCAG 2.3.1]; если чаще — площадь мигания ≤25% любого 10° поля зрения [С WCAG] или ≤25% экрана для эфира [С Ofcom, ITU-R BT.1702]; отдельно правило красных вспышек. Лаймовый хит ≥4 кадров [Э]. Проверка PSE-анализатором — см. «QA моушна».

## Материалы и фактура

### Принцип вкуса: современно, плоско, сатин

- [обязательно] Материалы простые и современные: плоский цвет, мягкие тени, сатин, матовый пластик, современное стекло. **Никакого старомодного детального 3D** (вкус клиента): без рендеров устройств и «железных» рамок, без зеркального хрома, без экструдированного хром-текста, без стеклянных трубок, пузырей и мениска, без микродеталей и фасок на «глине».
- [обязательно] Металл только сатиновый: roughness ≥0,18 (зеркальный хром читается старомодно).
- [по умолчанию] Тонмаппинг нейтральный, сохраняющий тон (AgX и подобные): ACES сдвигает насыщенные акценты. Bloom: порог 1,15, сила 0,15–0,3.
- [обязательно] Один материал героя и одна модель света на фильм; материалы не смешиваются с чужими моделями света.
- В коде: токены `material.hero3d.*`, `material.surface.*` (параметры three.js `MeshPhysicalMaterial`), `material.glass.*`, `light.model`, `texture.amount`; `HFT.three(theme)` отдаёт готовые материалы, окружение, тонмаппинг и bloom.

## Форма: радиусы, обводки, тени

### Формула радиуса

- [обязательно] **Одна формула на класс контейнера на весь фильм. Радиус = доля × короткой стороны элемента**: он масштабируется с контейнером и никогда не копируется с героя (внутри фана каждая карточка держит свою долю) [А].
- [обязательно] Вложенные радиусы концентричны: внутренний = внешний − паддинг (V20).
- [обязательно] Размеры и толщины — целые px после любого масштаба.
- [по умолчанию] Капсула: радиус = ½ меньшей стороны; внутренние радиусы согласуются с толщиной рамки.

Семьи формы (`shape`, доля короткой стороны; 0,5 = полная капсула). Канонические размеры: card 600×400, control 360×96, chip 200×48, media 1280×720, window 1440×900. Потолки: card 64, media 72, window 56 px [Э].

| Семья | card | control | chip | media | window | обводки: hairline / strong / accent, px |
|---|---|---|---|---|---|---|
| `sharp` | 0 | 0 | 0 | 0 | 0 | 1 / 2 / 3 |
| `soft` | 0,045 | 0,25 | 0,25 | 0,03 | 0,025 | 1,5 / 2 / 3 |
| `round` | 0,06 | 0,5 | 0,5 | 0,045 | 0,028 | 1,5 / 2 / 3 |
| `pill` | 0,12 | 0,5 | 0,5 | 0,08 | 0,05 | 2 / 3 / 4 |

Токены: `radius.chip`, `radius.pill`, `radius.control`, `radius.card`, `radius.cardSmall`, `radius.media`, `radius.panel`, `radius.window`, `radius.tile` (значение на опорном размере + доля в `$extensions`). Конкретные px каждого пресета — `styles.json → axes.shape`.

**Внешние радиусы tokens_universal** [стартовая настройка]: none 0, small 8, medium 20, large 40 du. Это фиксированные значения, а не доли: в системе используются только как стартовые для `soft`-семьи при отсутствии стиля.

### Обводки и наклон

- [обязательно] Хейрлайн 1–2 px; акцентная 2–4,5 px; цветная обводка, держащаяся только на цветности, ≥3–4 px (4:2:0); пунктир 18 / 12; ≥2 px на движущихся элементах [А+И].
- [обязательно] Наклон карточек ≤12°; скос стикера 7,4° (применяется к рамке, не к тексту); одно направление схода.
- Токены: `stroke.hairline`, `stroke.default`, `stroke.accent`. Внешние толщины tokens_universal [стартовая настройка]: fine 1, normal 2, strong 4, graphic 8 du.

### Тени

- [обязательно] **Одна формула тени на фильм**, по ярусам глубины: `shadow.float` (герой, ближний ярус), `shadow.card` (карточка в покое, средний), `shadow.near` (≈ y 18, blur 35, альфа 0,17 на тёмном, масштаб по материалу), `shadow.mid` (≈ y 9, blur 20, альфа 0,09), `shadow.window`, `shadow.contact`, `shadow.innerLight` (верхний внутренний свет).
- [обязательно] Свечения — тоже тени с нулевым сдвигом: `glow.action` (на светлой схеме становится цветной тенью y 12, blur 40, 25–35%), `glow.selected`, `glow.hero`.
- [по умолчанию] На светлом тень тонированная (INK = `fg.primary` светлой схемы), а не чистый #000.
- Внешние тени tokens_universal [стартовая настройка]: soft `DS(0, 16, 40, 0, #000, 14%)`, lifted `DS(0, 32, 72, 0, #000, 20%)` (в du).

### Логотип

**Универсально.**
- [обязательно] Логотип всегда **инстанс утверждённого файла** (`brandConfig.logoAsset`), никогда не перерисовывается; только `approvedLogoVariants`; охранное поле `logoClearSpaceDu` и минимальный размер `logoMinSizeDu`.
- [обязательно] Логотипы партнёров — только их официальные файлы и правила; цвета партнёра — только на объектах партнёра.
- [обязательно] Не зеркалить логотип в RTL-версиях.
- [по умолчанию] Логотип как бренд-пульс — 1–3 кадра на фильм; бренд-тайл в UI и водяной знак пульсами не считаются.

**Пример (Higgsfield):**
- Всегда **instance**, никогда не перерисовывается.
- Размеры: лаймовый 340×67; чёрный 470×92; белый 368×72 / 592×116 (аутро).
- Внутри UI — только squiggle. Как подпись — squiggle 64 px сверху по центру. Водяной знак — 1970–2194 px при 5–10%.
- В титуле логотип стоит **над** СЛОВОМ, высотой ≈0,4–0,6 от высоты капители. В ко-бренде — в ряду.
- Появляется как **бренд-пульс** (определение — в главе «Ритм и тайминг») не больше чем в 1–3 кадрах на фильм. Squiggle-тайл в UI и водяной знак пульсами не считаются.

### Бренд-глиф

[обязательно] Если у бренда есть глиф-подпись (звезда, знак, squiggle), он: несёт один смысл; живёт как векторный инстанс, никогда не набирается символом; входит в бюджет акцента; как орнамент появляется только через орнамент-кит фильма; мерцает ≤3 Гц.

**Пример (Higgsfield): Sparkle ✦ (4-лучевая звезда).**

- **Смысл.** Лайм = Higgsfield, а ✦ — его подпись: «генерация происходит или произошла». Внутри кнопки Generate ✦ живёт всегда. Как орнамент ✦ появляется только через **орнамент-кит фильма** (см. «Орнамент-киты») [А AV5 3/5: декоративные sparkle на титулах; AV3 8/11; AV4 6/11].
- **Размеры** (24–740 px):
  - токены 24 / 48 / 96 для UI и lockup;
  - триады 60/49/26 у точки действия (P3);
  - 33–55 px у концов слов;
  - 129 px розовые звёзды на билборде (P3);
  - **623–740 px** лаймовые звёзды, уходящие за противоположные углы светлых титулов и постеров (AV4 P5, P6).
- **Лимит.** 2–3 на lockup; **пары допустимы**, в том числе magenta слева + лайм справа (P4 130322). На кадр — одна группа sparkle плюс глиф в кнопке. Поворот 0° или 45°.
- **Геометрия мастер-вектора** [Э]: 4-лучевая звезда с вогнутыми сторонами; внутренний радиус (на 45°) ≈0,3 внешнего; стороны — кривые, без обводки, сплошная заливка. Варианты компонента 24 / 48 / 96, цвета лайм / белый / magenta / pink.
- **Никогда не набирайте ✦ символом** (U+2726): ни в Inter, ни в Space Grotesk этого глифа нет (проверено по файлам), и Figma и AE подставят системный шрифт. Только инстанс вектора.
- **Glow.** Белое ядро 6–10 px + 2 яруса ореола (8 и 32 px), или `DS(0, 0, 250, 0, #ADF537, 50%)`.
- **Анимация.** Scale 0 → 110% → 100% за 12 кадров; мерцание ≤3 Гц.
