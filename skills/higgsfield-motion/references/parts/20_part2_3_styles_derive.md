# Часть II. Стили, оси и жанры: как строить разные айдентики

Часть I описывает законы кадра, общие для любого бренда. Эта часть отвечает на вопрос «как выглядит фильм»: из каких независимых осей собирается стиль, какие 12 готовых пресетов есть, как жанр (задача фильма) сочетается со стилем (видом), как описать бренд и как построить новую айдентику. Законы `core` здесь не меняются: стиль меняет характер, а не законы.

**Как пользоваться за минуту.**
1. **Есть бренд с готовым видом** → `HFT.theme('<бренд>')`; оси не трогайте. Пример (Higgsfield): `HFT.theme('higgsfield')`.
2. **Нужен стиль под задачу** → выберите пресет по таблице «Как выбрать», при необходимости замените сид акцента на цвет клиента: роли и контраст пересчитаются (Часть III).
3. **Нужен свой стиль** → соберите его из значений осей: одно значение на ось; проверьте правила совместимости и пройдите `HFT.validate()`.
4. **Есть только цвет и настроение** → `HFT.derive({seed, mood})` (Часть III).
5. **Всегда** действуют законы `core` [обязательно]: смысловой текст ≥ 48 px в 16:9, ≤ 4 группы, hold ≥ max(1 с; 0,35 с × слова + 0,5 с), ≤ 3 вспышки в секунду.

## Архитектура: слои, порядок переопределений, тема

### Пять слоёв: core → axes → styles → brands → semantic

```
 ┌──────────────────────────────────────────────────────────────────────────┐
 │ CORE      законы, диапазоны, формулы, таблицы решений (core.json)        │  не темизируется
 └──────────────────────────────────────────────────────────────────────────┘
        ▲ ограничивает каждый слой ниже (проверяется в validate)
 ┌──────────────────────────────────────────────────────────────────────────┐
 │ AXES      typeVoice · palette · material · shape · motionPersonality ·   │  независимые
 │           composition · density · texture  (значение = пакет параметров) │  измерения
 └──────────────────────────────────────────────────────────────────────────┘
        ▼ одно значение на ось
 ┌──────────────────────────────────────────────────────────────────────────┐
 │ STYLES    пресет = {ось: значение} + переопределения внутри диапазонов   │
 │           core + whenToUse + do / don't                                  │
 └──────────────────────────────────────────────────────────────────────────┘
        ▼ ссылка на стиль
 ┌──────────────────────────────────────────────────────────────────────────┐
 │ BRANDS    айдентика = стиль + сиды, шрифты, слот логотипа, фирменный     │
 │           мотив, фирменный переход, более строгие законы, рецепты        │
 └──────────────────────────────────────────────────────────────────────────┘
        ▼ resolve(схема × формат)            derive(seed, mood, …) ─┐
 ┌─────────────────────────────────────────────────────────────────┴────────┐
 │ SEMANTIC  ролевые токены (bg.base, type.display, ease.enter …) + policy  │  единственный слой,
 │           + issues. Выдача: JS-объект, CSS-переменные, DTCG JSON, three  │  который читает код
 └──────────────────────────────────────────────────────────────────────────┘
```

| Слой | Владеет | Может ссылаться на | Не может содержать | Пример |
|---|---|---|---|---|
| `core` | диапазоны, формулы, лимиты, таблицы решений, семантический контракт, правила валидации | ни на что | цвета, имена шрифтов, ассеты бренда | «площадь акцента ≤ 8% (жёстко 10%)»; «hold = max(1,0; 0,35·w + 0,5)» |
| `axes` | именованные значения: пакеты параметров по измерению | диапазоны core | имена брендов, логотипы | `typeVoice.editorial-serif` = семейства, веса, кривая трекинга, регистр, фолбэки письменностей |
| `styles` | одно значение на ось + переопределения + `whenToUse`, `do`, `dont` | axes, core | сиды одной компании, логотипы | `luxury-serif` = {typeVoice: didone-luxury, motionPersonality: luxury-slow, …} |
| `brands` | сиды, точные hex, шрифты, слот логотипа, фирменный мотив и переход, более строгие законы, рецепты | один стиль, axes, core | правила мягче core | Пример (Higgsfield): стиль `higgsfield` + лайм #D1FE17 + Inter / Space Grotesk + «лайм = Higgsfield действует» |
| `semantic` | разрешённые ролевые токены по режиму + policy + происхождение + issues | только плоские значения | ссылки на имена осей в значениях | `accent.action` = #D1FE17; `ease.enter` = [0.05, 0.7, 0.1, 1] |

**Режимы** [обязательно]. Семантический слой разрешается по **схеме** (`dark`, `light`) × **формату** (`16x9`, `9x16`, `1x1`, `4x5`). От схемы зависят цвета, тени и свечения; от формата — кегли, метрики кадра и фокусные точки. Шрифты, кривые и длительности от режима не зависят.

### Конвейер разрешения `HFT.theme()` и `HFT.derive()`

1. **Загрузить core** (замороженный объект).
2. **Выбрать значения осей**: из стиля (`styles[name].axes`), из бренда (`brands[name].style` → его оси) или из `HFT.derive({seed, mood, typeVoice?, material?, motion?, scheme})` — настроение переводится в оси фиксированной таблицей, без случайности.
3. **Слить пакеты осей** в порядке typeVoice → palette → material → shape → motionPersonality → composition → density → texture. Поздние пакеты читают ранние (material берёт цвет свечения из palette).
4. **Применить переопределения стиля** — только ключи, которые пакет оси уже определяет.
5. **Применить переопределения бренда**: сиды, точные hex, семейства, слот логотипа, фирменный переход, более строгие законы.
6. **Применить проект, площадку и задокументированные исключения** (см. порядок ниже).
7. **Разрешить по режиму**: схема выбирает цветовые роли; формат — опорные кегли, `frame.*`, `focal.*`.
8. **Вычислить производные токены**: `accent.text` (минимальный сдвиг OKLCH-L по рампе до цели), `accent.edge` и режим fill-only, если заливка не даёт нетекстовые 3:1; `fg.onAccent`; свечение → цветная тень на светлой схеме; `dur.* = база × m` в пределах токена, квантовано в целые кадры; кадры при `rhythm.fps`; полы читаемости по метрикам шрифта; `policy.type.framePairs`.
9. **Проверить** правилами V01–V21 (Часть III, «validate()»). `HFT.validate()` возвращает `issues[] = {id, severity, token, message, value, limit}`; `HFT.derive()` сам исправляет (зажимает диапазоны, поднимает цвета, меняет фолбэки письменностей, увеличивает кегль) и пишет каждое исправление в `meta.fixes`.
10. **Детерминизм** [обязательно]: одинаковый вход → побайтно одинаковый выход. Без `Date`, без `Math.random`, ключи объектов отсортированы.

Вызов с жанром: `HFT.theme({style: 'swiss-editorial', genre: 'dataStory', scheme: 'light', format: '16x9'})` — жанр добавляет модули, порядок действия и проверки, но не меняет вид (см. «Жанр × стиль»).

### Порядок переопределений: от базы к исключению кадра

Слои применяются снизу вверх; каждый следующий может менять только то, что разрешено ему и не выходит за `core` [обязательно]. Порядок взят из `tokens_universal.json` (`formatContract.overrideOrderLowToHigh`) и совмещён с нашими слоями.

| # | Уровень (низ → верх) | Что задаёт | Где живёт | Пример |
|---|---|---|---|---|
| 1 | **base** — базовые токены | законы, диапазоны, семантический контракт | `core` (+ пакеты осей) | hold-формула, полы кегля, лимит вспышек |
| 2 | **style preset** | одно значение на ось + переопределения внутри диапазонов | `styles.*` | `kinetic-type`: poster-type-led, overshoot 0,06 |
| 3 | **brand** | сиды, hex, шрифты, логотип, мотив, фиксированные значения цветов, более строгие законы, замки | `brands.*` | Пример (Higgsfield): «лайм никогда не текст на светлом» ужесточает V03 до «никогда, ни в каком кегле» |
| 4 | **project** | бриф конкретного фильма: длительность, fps / BPM, язык, модули, CTA, жанр | `spec.project` | 30 с, 25 fps, кириллица, модуль `promptFlow` |
| 5 | **delivery** | требования площадки: формат, safe-зоны, оверлеи, кроп-варианты, альфа, HDR, громкость | `spec.delivery` | 9:16 для ленты: зона интерфейса снизу, субтитры выше |
| 6 | **documented shot exception** | осознанное отступление в одном шоте | `spec.exceptions[] = {shot, token, value, reason, approvedBy}` | бит 4: 6 фокусов намеренно (коллаж-нарезка под бит) |

- **Исключение записывается вместе с причиной** [обязательно]. Без записи — это ошибка, а не исключение.
- **Никакое переопределение не отменяет** [обязательно] достоверность данных, целостность ссылок и требования площадки сдачи (`overrideRuleRu` внешней системы).
- **Границы.** Стиль или бренд может поставить любое значение *внутри* диапазона core (максимум акцента 6% там, где настроение разрешает 8%; overshoot 0,04 при капе 0,12), но никогда вне его (площадь акцента 20% при потолке 18%; body 18 px при абсолютном поле 20 px) [обязательно].
- **Законы бренда** могут быть только строже core [обязательно].
- **Рецепты** (раскладки кадров с координатами, фирменные переходы и мотивы) живут только в `brands.*`; core хранит их общую форму [по умолчанию].
- **Замки.** Бренд может запереть ключи осей (`brand.locks = ['typeVoice', 'palette.seed']`), чтобы смена стиля не сломала айдентику [по умолчанию].

### Объект темы и выдача

```js
theme = {
  meta:   { id, name, brand, style, genre, scheme, format, axes:{typeVoice,…}, coreVersion:'1.0.0', fixes:[] },
  tokens: { 'bg.base': {$type:'color', $value:{colorSpace:'srgb', components:[…], hex:'#131313'},
                        $extensions:{'ai.higgsfield.hft':{oklch:[0.187,0,0], from:'palette.neutrals'}}}, … },
  policy: { composition, density, accent, type, transitions, camera, texture, light, reading, formats, contexts },
  issues: [ {id:'V06', severity:'error', token:'type.body', value:58, limit:64, message:'…'} ]
}
```

| Выход | Хелпер | Правило |
|---|---|---|
| DTCG JSON (Design Tokens Format Module 2025.10) | `HFT.theme()` | цвет `$value` = `{colorSpace:'srgb', components:[r,g,b], alpha?, hex}`; dimension = `{value, unit:'px'}`; duration = `{value, unit:'ms'}`; typography = `{fontFamily, fontSize, fontWeight, letterSpacing (px), lineHeight}`; нестандартное — в `$extensions["ai.higgsfield.hft"]`. `letterSpacing` в DTCG не держит em и %, поэтому выдаётся `trackingEm × fontSize` по формату, em остаётся в `$extensions`. Имя, которое и токен, и группа (`stagger`, `stagger.line2`), выдаётся как `stagger.$root` |
| CSS-переменные | `HFT.toCSSVars(theme)` | `--{prefix-}{path}`: `.` → `-`, camelCase → kebab-case (`bg.base` → `--bg-base`; `type.display` → `--type-display-family`, `-size`, `-weight`, `-tracking`, `-leading`); cubicBezier → `cubic-bezier(…)`, длительность → `ms`, тень → полный список CSS |
| Шрифты | `HFT.fontLink(theme)` | один URL css2, оси по алфавиту, `opsz` где есть, `display=block` |
| three.js | `HFT.three(theme)` | `material.*` 1:1 в параметры `MeshPhysicalMaterial`; цвета — sRGB hex, перевод в linear делает потребитель |

**Регистр и правила голоса.**

- **`neo-grotesk`** (Нео-гротеск). Дисплей: sentence (утверждение с точкой допустимо); лейблы: CAPS только ≤36 px. Правила: opsz = 32 для всего ≥32 px (font-optical-sizing:auto); ниже — opsz по кеглю; 'case' на CAPS с пунктуацией, 'tnum' на всех меняющихся числах; вес не меняется внутри строки; акцент — цветом, контейнером или материалом.
- **`grotesk-tech`** (Тех-гротеск). Дисплей: CAPS; лейблы: CAPS +0.12…+0.16 em на 15–28 px (HUD, теги). Правила: Space Grotesk никогда не наклоняется (italic нет); «слово скорости» — Inter Bold Italic; ширина почти не меняется с весом (300→700 <1%): вес можно анимировать без переразбивки; кириллица и греческий → Inter тем же весом, кегль ×0,96 (капитель 0,70 / 0,728).
- **`humanist`** (Гуманист). Дисплей: sentence; лейблы: CAPS +0.08 em ≤32 px. Правила: FLAR (вспышка на концах штрихов) 0–40: выше 40 читается как декоративный шрифт; VOLM держать 0 на тексте, до 40 только на дисплее ≥120 px.
- **`geometric`** (Геометрический). Дисплей: sentence; лейблы: CAPS +0.10…+0.16 em (геометрическим капителям нужен воздух). Правила: CAPS-дисплей ≥120 px не используем (круглые O/C/G разваливают ритм); Plus Jakarta Sans не отдаёт базовую кириллицу (только cyrillic-ext) → кириллица в Manrope.
- **`editorial-serif`** (Редакционная антиква). Дисплей: sentence + одно слово италиком; лейблы: CAPS +0.10 em, набор в гротеске текста. Правила: на ≥120 px вес 300–400: контраст даёт opsz, а не жирность; италик того же семейства = акцент; другой серифный шрифт рядом запрещён; Fraunces без кириллицы → Literata (opsz 72) тем же весом.
- **`didone-luxury`** (Дидона / люкс). Дисплей: sentence или разреженные CAPS (+0.04…+0.08 em); лейблы: Jost 500 CAPS +0.20…+0.28 em. Правила: Playfair: капитель 0,571 em (файл шрифта) → для равной капители с Inter кегль ×1,27; дисплей не жирнее 600: волосяные штрихи на 4:2:0 должны быть ≥2 px → Playfair ≥120 px; opsz = кегль (font-optical-sizing:auto) — на больших кеглях контраст растёт сам; Bodoni Moda только латиница → для кириллицы Playfair.
- **`condensed-display`** (Узкий дисплей). Дисплей: CAPS; лейблы: CAPS широкий трекинг. Правила: узкий только CAPS-дисплей; текст — в нормальной ширине того же семейства; Sofia Sans Extra Condensed: средняя ширина знака 0,27 em → ≈45% уже Inter, ≤30 знаков на строку при 152 px; «Big Shoulders Display» из старых документов теперь «Big Shoulders» (opsz 10–72); веса 200–400 CAPS: +0.18…+0.30 em (титровый набор).
- **`expanded-display`** (Широкий дисплей). Дисплей: CAPS или sentence; 1–3 слова; лейблы: CAPS +0.08 em. Правила: ≤8–10 знаков на строку при 200 px (Unbounded ≈0,6 em/знак); широкий шрифт не ставим в длинные строки и субтитры.
- **`mono-terminal`** (Моно / терминал). Дисплей: lowercase-команды, `>`/`$`, [скобки] для лейблов; лейблы: CAPS +0.04 em. Правила: моноширинный дисплей «рыхлый» — трекинг сильнее, чем у гротеска на тот же кегль; tnum встроен; счётчики не дрожат; Martian Mono: капитель 0,80 em (файл шрифта) → кегль ×0,91 к Inter для равной капители.
- **`rounded-friendly`** (Скруглённый). Дисплей: sentence; лейблы: sentence. Правила: Rubik отдаёт арабский и иврит — один шрифт на три письменности; CAPS-дисплей не используем: скругления читаются как «детский» шрифт.
- **`quirky-grotesk`** (Характерный гротеск). Дисплей: sentence или lowercase; лейблы: sentence. Правила: opsz 96 на дисплее (детали тоньше), opsz 12 — «грубый» акцент того же семейства; wdth 75↔100 можно анимировать на ударной доле; Bricolage без кириллицы → Rubik 800 (капитель 0,70 против 0,66: кегль ×0,94).
- **`variable-kinetic`** (Вариативный кинетический). Дисплей: CAPS 1–3 слова; лейблы: CAPS +0.08 em. Правила: анимируем wdth/wght, а не scale: капитель постоянна, ритм строк не прыгает; переносы планируем по самому широкому состоянию (+25% длины строки); Mona Sans без кириллицы → Roboto Flex (те же оси wdth/wght); трекинг = базовый − 0,02 × (wdth − 100) / 25 (на wdth 125 ещё −0,02 em; на 75 — +0,02 em).
- **`pixel`** (Пиксель / точечная матрица). Дисплей: CAPS или цифры; лейблы: CAPS. Правила: отрицательный трекинг запрещён: точки/пиксели слипаются; Doto только ≥96 px (на меньших кеглях точки сливаются в 4:2:0); Tiny5: кегль кратен 8 px, чтобы пиксель шрифта = целому числу px; Doto без кириллицы → DotGothic16 (пиксельная готика, тоже кириллица и японский).

### `palette` — генерация палитры в OKLCH из 1–2 сидов

| Режим | Нейтрали (C) | Потолок C акцента | Как работает цвет |
|---|---|---|---|
| `signal` | 0.004 | 0.4 | почти ахроматичные нейтрали + один насыщенный акцент на пределе охвата sRGB; второй акцент ≥90° по тону, ≤3–5% |
| `tonal` | 0.012 | 0.14 | нейтрали подкрашены тоном сида (C 0,010–0,025), акцент средней насыщенности; цвет как атмосфера |
| `duotone` | 0.01 | 0.4 | два сида работают полями (колор-блоки 10–35%), текст — тёмный инк на светлых полях |
| `pastel` | 0.008 | 0.18 | акценты в светлых полях (L 0,80–0,92, C 0,06–0,12) + одна насыщенная ступень для действия; mesh-градиенты из ≤2 тонов |
| `mono` | 0 | 0.4 | ахроматика; акцент — инверсия ч/б, свечение или размер; цветная точка-статус ≤0,5% площади |
| `spectral` | 0.01 | 0.2 | холодные «хромовые» нейтрали + иридесцентный переход между двумя сидами по короткой дуге OKLCH (≤12% площади) |

**Алгоритм (детерминированный; так же работает `derive()`):** [обязательно]

1. seed → OKLCH (Ls, Cs, Hs). Нейтрали: hue = neutralHue (или seed), chroma = mode.neutralChroma (signal 0,004 … tonal 0,012–0,014; mono 0).
2. Ramp акцента: L = rampL[k], C = min(Cs × taper[k], mode.accentChromaCap, maxChroma_sRGB(L, Hs)); ключ 'seed' = точный hex.
3. Тёмная схема: bg.base L = darkBaseL (0,13–0,18); sunken −0,045 (≥0,10); raised +0,04; card +0,06; overlay +0,08; input +0,10; fg.primary L 0,95 (C×0,6); fg.muted 0,76; fg.subtle 0,60. Линии — альфа fg.primary поверх bg: hairline на композит 1,25:1, strong на 1,6:1 (как в derive(), Часть III).
4. Светлая схема: bg.base L = lightBaseL (0,93–0,99); raised/card = +0,025 (белый при ≥0,995); sunken и input −0,035; overlay −0,06; fg.primary L 0,20 (inkHue); fg.muted 0,47; fg.subtle 0,60; линии — так же альфой.
5. accent.action — тёмная: seed, если ≥3:1 к bg, иначе светлее по ramp; светлая: pastel → первая ступень с белым текстом ≥4,5:1; seed L ≥0,80 → «маркер» (seed заливкой + край A700 + инк-текст); иначе seed или темнее до ≥3:1.
6. accent.onAction — из {белый/fg.primary, инк}: оставить пары с WCAG ≥3:1 и |Lc| ≥45, выбрать максимум |Lc| (APCA точнее для насыщенных средних тонов: белый на красном #E4321B — Lc 74 при WCAG 4,4).
7. accent.text — первая ступень от seed в сторону контраста с WCAG ≥4,5:1 и |Lc| ≥60; accent.core = A50; accent.subtle = OKLab-микс bg→seed 12–14%; accent.glow = seed 30% (тёмная) / цветная тень A600 35% (светлая).
8. accent2/accent3 — тот же алгоритм; второй акцент ≥90° по тону от первого (кроме пресетов, где он — свет/статус).
Совместимость с derive(): каждая схема также содержит псевдонимы fg.onAccent (= accent.onAction), accent.seed, accent.secondary / accent.secondaryText (= accent2.*), line.focus, line.strong.
9. override пресета (точные значения айдентики) применяется последним; затем validate(): fg.primary ≥12:1 & |Lc|≥90; fg.muted ≥4,5:1 & |Lc|≥45 (≥32 px); fg.subtle ≥3:1 & |Lc|≥30 (только мета); onAction ≥3:1 & |Lc|≥45 (текст на заливке всегда ≥32 px); action/bg ≥3:1 & |Lc|≥15 или режим «маркер»; accent.text ≥4,5:1 & |Lc|≥60.

**Ступени ramp (OKLCH L) и сужение хромы на краях:**

| Ступень | 50 | 100 | 200 | 300 | 400 | 500 | 600 | 700 | 800 | 900 | 950 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| L | 0.97 | 0.935 | 0.88 | 0.82 | 0.75 | 0.68 | 0.6 | 0.52 | 0.44 | 0.36 | 0.28 |
| C × | 0.35 | 0.6 | 0.85 | 1 | 1 | 1 | 1 | 1 | 0.9 | 0.8 | 0.7 |

**Площадь акцента по настроению** (доля кадра, свечения не считаются; второй акцент ≤ трети первого):

| Настроение | Цель | Максимум |
|---|---|---|
| calm | 1–4% | 6% |
| luxury | 1–3% | 4% |
| editorial | 2–6% | 8% |
| technical | 2–8% | 10% |
| energetic | 6–15% | 25% |
| playful | 12–30% | 40% |

**Пороги `validate()`** [обязательно] (WCAG 2.x и APCA; берём более строгий): `fg.primary` ≥12:1 и |Lc| ≥90; `fg.muted` ≥4,5:1 и |Lc| ≥45 (текст ≥32 px); `fg.subtle` ≥3:1 и |Lc| ≥30 (только мета ≥24 px CAPS); текст на заливке действия ≥3:1 и |Lc| ≥45 (всегда ≥32 px); заливка к фону ≥3:1 и |Lc| ≥15, иначе режим «маркер» (край или цветная тень); акцентный текст ≥4,5:1 и |Lc| ≥60.

**Общие цветовые правила:** [обязательно] градиенты строим в OKLCH и только между тонами ≤120° друг от друга (иначе середина грязнится; лайм → magenta даёт оранжевый #DF8A44); цветной текст ≥40 px и цветные линии ≥3–4 px (4:2:0); тёмный градиент покрывает ≥20 кодовых значений, иначе бандинг; смысловой контент не темнее #131313 (Rec.709 Y′ 32).

`INK` в рецептах = `fg.primary` светлой схемы (тонированная тень), `A…`/`N…` = ступени ramp акцента и нейтралей. В `styles.json` у каждого пресета эти токены уже подставлены.

**Появление текста:**
- `productive`: маска строки снизу вверх; строка 2 через 3–4 кадра; подсветка ещё через 4–6.
- `expressive`: по словам: scale 0,9→1 + blur 8→0 px, шаг 2 кадра.
- `luxury-slow`: opacity 0→1 + y +12→0 px + трекинг +0,06 em → целевой за 1,2 с; строки через 8 кадров.
- `playful-bouncy`: по словам: pop scale 0→1,08→1 (back-out), шаг 2 кадра; заголовок ≤6% overshoot.
- `cinematic`: blur 12→0 + opacity за 18 кадров; трекинг дрейфует −0,01 em за шот.
- `glitch-tech`: type-on 24–40 знаков/с с кареткой (12 кадров вкл / 12 выкл) или scramble 8–12 кадров на слово.

Пружина `playful-bouncy` для кода: f = 2 Гц, ζ = 0.6 → overshoot 9.5%, установка (2%) за 0.53 с; x(t)=1−e^(−ζωt)(cos ω_d t + ζω/ω_d · sin ω_d t), ω=2πf, ω_d=ω√(1−ζ²). Ограничения `glitch-tech`: RGB-сдвиг ≤4 px на 1–2 кадра; вспышки ≤3/с (WCAG 2.3.1), площадь мигания ≤25% кадра.

**Грамматика переходов** (имена в таблице выше):

- `match-cut` — объект/форма совпадает по позиции (±200 px) и масштабу через склейку.
- `push` — вся сцена сдвигается на ширину кадра или колонку; один easing на группу.
- `whip` — скоростной пан 4–8 кадров размытия; ≤1 на 15 с.
- `mask` — вайп/ирис/маска по форме объекта или по колонке сетки.
- `flash` — вспышка ≤2 кадра, ≤3/с, лаймовый/цветной хит ≥4 кадров.
- `morph` — форма A перетекает в форму B (pill → bar, кнопка → карточка).
- `dissolve` — кросс-растворение 12–24 кадра (люкс, кино).
- `dip` — уход в цвет фона/чёрный 8–12 кадров.
- `hard-cut` — прямая склейка на долю.
- `glitch-slice` — 4–8 горизонтальных полос со сдвигом 2–4 кадра.

### Совместимость осей [обязательно]

- `neon-light` только на тёмной сцене; на светлой он автоматически становится цветной мягкой тенью.
- `glass-modern` требует изображения или градиента под стеклом; с `texture: none` и плоским фоном не используется.
- `luxury-slow` и `cinematic` несовместимы с `density: rich` (длинные холды + много элементов = перегруз).
- `playful-bouncy` не сочетается с `didone-luxury` и `condensed-display`: пружина ломает тон шрифта.
- `pixel` и `mono-terminal` — только `shape: sharp` или `round` (точки); `pill` спорит с сеткой символов.
- `palette: mono` + `motion: glitch-tech` + `flash`: следить за правилом ≤3 смен полярности в секунду.
- `pastel` никогда не даёт цвет текста; текст — инк, действие — насыщенная ступень с белым текстом.

### Различимость

- Любые два пресета различаются минимум по **4 из 8 осей** и всегда разным дисплейным семейством (совпадений: 0). Палитра, шрифт, материал и моушн вместе дают узнаваемый силуэт стиля даже в ч/б.
- Самые близкие пары: higgsfield ↔ swiss-editorial (4 оси, Δтон акцента 91°); tech-terminal ↔ brutalist-raw (4 оси, Δтон акцента 123°); swiss-editorial ↔ tech-terminal (4 оси, Δтон акцента 174°); luxury-serif ↔ cinematic-noir (5 осей, Δтон акцента 15°).
- Тоны основных акцентов (OKLCH H): swiss-editorial 31°, organic-editorial 42°, cinematic-noir 68°, luxury-serif 83°, brutalist-raw 94°, higgsfield 122°, tech-terminal 217°, y2k-chrome-modern 221°, kinetic-type 269°, soft-pastel-ui 288°, playful-pop 358°, dot-matrix ахроматичный. Где тоны близки, пресеты расходятся хромой, материалом и шрифтом (cyan `tech-terminal` против ice `y2k-chrome-modern`: сигнал против иридесцентного перехода).

**Правило выбора** [по умолчанию]: один пресет на фильм. Смешивать можно только через оси (своя сборка) с проверкой совместимости, а не «немного от двух пресетов» в соседних кадрах. Если у клиента свой цвет — меняется только сид акцента, остальное пересчитывает `HFT.derive()`.

### Алиасы внешних пресетов (`tokens_universal.json`)

Клиентская система (`tokens_universal.json`) приносит 7 «тонких» пресетов. Они **не заменяют** наши: им не хватает чисел (общая индиго-палитра, Inter + ui-monospace по умолчанию, совет «выбирать по задаче»). `HFT.theme()` принимает их имена как алиасы и разрешает в наш пресет [обязательно]:

| Их пресет | Их описание (тема · материал · движение · раскладка) | Наш пресет |

## Жанр × стиль

**Жанр = работа, стиль = вид** [обязательно]. Жанр отвечает на вопрос «что фильм делает» (показывает продукт, объясняет, выражает бренд, ведёт данные…) и задаёт обязательные входные данные, модули, порядок действия и проверки. Стиль отвечает на вопрос «как он выглядит» (оси и пресет). Оси независимы: любой жанр можно снять в нескольких стилях, и жанр не меняет ни одного токена вида. В коде: `HFT.theme({style, genre})`, профили — `HFT.genres`, модули — `HFT.modules`. Профили взяты из `tokens_universal.json` (`genreProfiles`) [стартовая настройка].

**Моушн-заметки жанров** [по умолчанию]:
- `productDemo`: связывать действие в интерфейсе с видимым откликом и результатом; задерживать важные состояния; камера и акценты — только там, где помогают следить за действием.
- `explainer`: вводить элементы в порядке, который объясняет связь; сохранять опорные элементы между шагами; пауза на сложной схеме, лишние детали убирать.
- `brandFilm`: пластика — из характера бренда; развивать один мотив или связанные мотивы; спокойствие, паузы и контраст — полноценные средства, кульминация не обязательна.
- `kineticType`: движение следует интонации; различать текст для чтения и буквы как форму (решается в брифе); длительность показа проверять вместе с длиной строки и характером движения.
- `logoIdent`: жест строится из формы знака или идеи бренда; длительность и конечное состояние — по месту использования; деформация, объём, свет, звук — по задаче.
- `dataStory`: анимация значений и шкал не создаёт ложную величину или причинность; оси и единицы сравнимы, изменение шкалы показано явно; промежуточные кадры твина отделены от измеренных точек.
- `editorialTitles`: ритм титров согласован с соседними сценами и музыкой; один повторяемый принцип для имён и глав; переход в произведение — часть последовательности.
- `characterMotion`: позы и тайминг — от намерения персонажа; вес, инерция, деформация реалистичны или условны, но поддерживают характер; ясность через позу, взгляд, силуэт.
- `spatial3d`: статичная камера — полноценное решение; физика и материалы реалистичны, условны или абстрактны; движение объекта, камеры и среды разделены.
- `broadcastPackage`: у каждого элемента есть вход, удержание, обновление, выход; удержание управляется оператором, длина контента переменная; общие принципы движения при разных функциях.
- `musicVisual`: связь с ритмом, фразой, тембром — по замыслу; не каждый удар требует события, паузы и полиритмия выразительны; в живом показе разделять заранее заданные события и управляемые в реальном времени.

**Исключения, которые разрешает жанр** [исключение]:
- Коллаж, танец, музыкальная нарезка (`musicVisual`, `kineticType`, `brandFilm` в стиле `maximal-collage`) могут держать несколько фокусов намеренно; это пишется в `spec.exceptions[]`.
- Буквы как фактура (`kineticType`, `musicVisual`) могут не читаться, но must-read текст отделён от фактуры и проходит все полы читаемости.
- Логотип, хук, UI и CTA появляются только там, где жанр их требует: в `explainer` или `editorialTitles` CTA по умолчанию нет; в `logoIdent` нет UI.

## Схема бренда (`brandConfig`)

Бренд = один стиль + то, что принадлежит только этой компании. Схема полей взята из `tokens_universal.json` (`brandConfig`) и расширена нашими полями слоя `brands` (стиль, замки, законы, рецепты, фирменный переход, мотивы, ритм). Каждый `HFT.brands.*` заполняет эту схему; `null` = «не задано» (не ноль) [обязательно].

## Как добавить шрифтовую пару

1. **Семейство есть в Google Fonts** (`fonts.google.com/metadata/fonts`), а css2-спек с нужными осями отвечает HTTP 200 (скрипт `_work/css2check.py`) [обязательно].
2. **Письменности проверены по реально отданным subsets** в CSS, а не по названию семейства: `cyrillic` = базовая кириллица U+0400–045F. Если нужного subset нет — назначьте двойника той же классификации и посчитайте `scale = cap(основной) / cap(двойника)` (для строчных — по x-height) [обязательно]. Скрипты внутри слова не смешиваются: роль целиком переходит в замену.
3. **Дисплей и текст контрастируют классом или шириной**, а не мелкими деталями: гротеск + антиква, узкий + нормальный, моно + гротеск. Два похожих гротеска рядом (например Plus Jakarta Sans + Manrope) читаются как ошибка [обязательно].
4. **Задайте трекинг по 5 полосам** (≥200, 120–200, 80–120, 48–80, 20–48 px), интерлиньяж (дисплей 1 / 2 строки / CAPS / текст / UI) и регистр; трекинг зажимается полосой core [по умолчанию].
5. **Прогоните styleboard**: на ≥ 48 px нет слипания, на 4:2:0 волосяные штрихи ≥ 2 px; `HFT.validate()` без ошибок V06–V11 [обязательно].
6. **Лимиты набора** [обязательно]: ≤ 2 нарративных семейства + ≤ 1 акцентный (на одно слово) + ≤ 1 моно (V10).
7. **Обновите реестр**: семейство, оси, письменности, капитель, где используется (таблица «Реестр шрифтов» выше); снимок `FONT_DB` обновляется при каждом новом голосе.

**Известные ловушки** (проверено 2026-10-08):
- «Big Shoulders Display» больше нет в Google Fonts: семейство называется **Big Shoulders** (opsz 10–72, wght 100–900).
- **Plus Jakarta Sans** отдаёт только `cyrillic-ext`, без базовой кириллицы → кириллица в Manrope.
- Без кириллицы: Space Grotesk, Space Mono, Instrument Serif, Instrument Sans, Doto, Fraunces, Bricolage Grotesque, Mona Sans, Anybody, Archivo, Bodoni Moda, DM Mono, Syne, Libre Caslon Text — у каждого пресета для них задан кириллический двойник.
- Предпочтительные кириллические замены в `derive()`: Space Grotesk → Inter Tight · Space Mono / DM Mono → JetBrains Mono · Plus Jakarta Sans → Manrope · Fraunces → Literata · Bricolage → Onest · Doto → DotGothic16. # Часть III. derive(): новая айдентика из цвета и настроения

`HFT.derive()` строит полную тему (цвета обеих ролей, тип, форму, моушн, материал, policy) из 1–2 seed-цветов и 1–2 настроений. Это исполняемая часть законов: числа взяты из Библии (типографика, цвет и свет, радиусы, моушн) и ресерча (`typography.md`, `color-light.md`, `motion-principles.md`, `brand-higgsfield-motions.md`). Где правило Higgsfield обобщено на любую айдентику, это сказано явно.

**Когда использовать** [по умолчанию]: у клиента есть только цвет (или два) и настроение; нужен нейтральный «образец» вместо чужой палитры; нужно быстро проверить, выдержит ли цвет бренда контраст и бюджет. Если у бренда уже есть утверждённый вид — `HFT.theme('<бренд>')`; derive тогда служит проверкой и источником производных (`accent.text`, `accent.edge`, состояния).

**Файлы:**
- **Прототип:** `derive.proto.js` (без зависимостей; браузер — `window.HFTDerive`, Node — `module.exports` с `derive`, `normalise`, `validate`, `toCSSVars`, `fontLink`). В `hf-tokens.js` он становится `HFT.derive`.
- **Проверка:** `node derive.proto.js` печатает self-test, 4 выведенные темы и светлую версию темы A; `--json` выдаёт полный JSON; `--css` дописывает CSS-переменные темы A.
- **Контракт:** `core.json` 1.0.0, разделы `semanticContract` и `validation` V01–V21. Имена токенов, пороги контраста, бюджет акцента, семейства формы и формулы моушна совпадают с core.

**Метки доказательности** внутри этой части: **[С]** — стандарт, **[И]** — исследование, **[А]** — архив (наблюдение по утверждённым кадрам), **[Э]** — наша эвристика. Ссылки вида «§6.1» в метках — на разделы Библии.

**Что нового в v0.2 по сравнению с v0.1:**
1. Выход — **канонические имена** `core.json`: 146 из 167 токенов контракта; 21 недостающий — константы формата `space.* / frame.* / focal.*`, их добавляет `resolve()`. Ни одного имени вне контракта.
2. Внутри три слоя:
   - `CORE` — зеркало `core.json`;
   - `AXES` — зеркало значений осей из `_work/axes.py`: гарнитуры голосов, кривые и множители моушна, режимы палитры;
   - `MOODS` — собственная таблица derive.

   Любое значение оси или настроения, вышедшее за границу core, зажимается, и это пишется в `meta.fixes` (`ARCHITECTURE.md` §1.3, шаг 8).
3. Валидация отдаёт `issues[] = {id, severity, token, message, value, limit}` с id V01–V21 из core.
4. Новое по сути:
   - режимы палитры (signal, tonal, duotone, pastel, mono, spectral);
   - `bg.overlay` — альфа скрима решается под контраст текста;
   - правило для `state.positive` / `state.negative`;
   - `policy.type.framePairs`;
   - правило градиента между акцентами (V16).

## Контракт `HFT.derive()`

```js
const theme = HFT.derive({
  seed: '#D1FE17' | ['#000000', '#E4002B'],   // 1–2 seed-цвета
  mood: 'technical' | ['editorial', 'calm'],  // calm | luxury | energetic | playful | technical | editorial; ≤ 2
  scheme: 'dark' | 'light',                    // по умолчанию 'dark'
  // необязательные переопределения осей (иначе из mood):
  typeVoice, motion, material, shape, composition, density, texture, palette,
  // контекст кадра:
  format: '16x9' | '9x16' | '1x1' | '4x5',     // по умолчанию '16x9'
  viewing: 'feed' | 'fullscreen',              // по умолчанию 'feed'
  contexts: ['feed16x9', 'tv16x9'],            // вместо viewing; берётся самый строгий
  script: 'Latn' | 'Cyrl' | 'Grek' | 'Jpan' | 'Kore' | 'Hans' | 'Hant' | 'Arab' | 'Deva' | 'Hebr', // или имя сабсета GF
  fps: 24,                                     // 24 | 25 | 30 | 48 | 50 | 60
  fidelity: 'adaptive' | 'exact',              // можно ли сдвигать заливку seed (см. «Акцент: заливка…»)
});
// → { meta, tokens, policy, ramps, detail, checks, issues }
```

| Поле | Содержимое |
|---|---|
| `meta` | `id` = `drv-<fnv1a(canonical input)>`; `scheme`, `format`, `contexts`, `axes` (8 осей); `drivers`: energy, ratio, bgL, хрома нейтралей, относительная хрома seed, m, сработавшее парное правило; `input`; `fixes[]` = {token, from, to, rule, reason} |
| `tokens` | семантический слой: что потребляет код («Токены и выдача») |
| `policy` | `composition`, `density`, `accent`, `type`, `transitions`, `camera`, `texture`, `light`, `reading`, `formats`, `contexts` (Часть II, «Policy темы») |
| `ramps` | 12 нейтралей; 12 шагов акцента, `action` закреплён на ближайшем шаге |
| `detail` | шкала типа по шагам, пороги читаемости, кривая трекинга, реальные семейства по ролям, стек ореолов glow |
| `checks` | таблица контраста: WCAG, APCA, floor, target, pass |
| `issues` | результат `validate()` (раздел «`HFT.validate()`») |

**Гарантии** [обязательно]:
- **Детерминизм.** Нет `Math.random`, `Date` и сети. Любой цвет проходит цепочку «OKLCH → gamut map → 8-битный hex → повторный замер OKLCH», поэтому вывод побайтно повторяем. Self-test сравнивает два прогона через `JSON.stringify`.
- **Валидность.** В выданной теме нет `error`. Стресс-прогон: 2759 тем, 0 ошибок, ≈ 1,1 мс на тему. Прогон покрывает:
  - 20 seed × 6 mood × 2 схемы × 2 fidelity;
  - 13 голосов × 8 письменностей × 4 формата × 2 просмотра × 2 схемы;
  - 6 персональностей × 6 mood × 6 fps;
  - все пары настроений;
  - 7 материалов × 4 формы × 6 режимов палитры × 2 схемы;
  - мультиконтексты.
- **Бренд-верность.** `accent.seed` — всегда исходный hex, для логотипа. Любой сдвиг `accent.action` записан в `meta.fixes`.

## Конвейер и правило коррекции

```
normalise ─► mood → оси (парные правила, смешивание 0,7 / 0,3) ─► анализ seed
 ─► нейтрали (режим палитры) ─► bg.overlay ─► accent: action → fill-only/edge → onAccent → text
 ─► secondary, states ─► линии, atmos, glow.pool ─► бюджет площади ─► тип ─► форма ─► моушн ─► материал
 ─► tokens + policy ─► contrastChecks ─► validate
```

**Одно правило коррекции на все шаги** [обязательно]:
1. Генерация целится в **target** роли.
2. Валидация падает только ниже **floor**. Между floor и target — предупреждение.
3. Если роль не дотягивает, цвет двигается по OKLCH-светлоте **на минимальную величину**: тон фиксирован, относительная хрома `C / maxChroma(L, H)` сохраняется.
4. Сначала цвет двигается **от фона** — так он не теряет контраст с землёй.
5. Значения осей и настроений, вышедшие за core, зажимаются: результат идёт в `meta.fixes`, сообщение — в `issues` с уровнем info.

## Цветовая математика

- **sRGB ↔ linear ↔ OKLab ↔ OKLCH:** матрицы Оттоссона (2020), они же в CSS Color 4.
- **Gamut mapping:** CSS Color 4 §13.2 — двоичный поиск по хроме, JND ΔE_OK 0,02, ε 0,0001. Тон при отсечении в пределах JND может уйти на 2–3°.
- **`maxChroma(L, H)`:** 26 итераций двоичного поиска, с кешем. Рампы держат относительную хрому seed: у лайма она 0,985, он стоит на куспе своего тона.
- **WCAG 2.x:** кусочная линеаризация.
- **APCA-W3 0.0.98G-4g:** константы SA98G сверены с исходником Myndex/apca-w3; |Lc|.
- **Яркостный код BT.709:** `16 + 219·Y′` — что переживёт 4:2:0.
- **Композит альфы:** в гамма-sRGB, как в Figma и 8-bpc AE.
- **Self-test сверяет эталоны Библии (цвет, §6.2) и ресерча:**
  - лайм / #131313 = 15,84:1;
  - #A2A2A2 / #131313 = 7,28:1;
  - белый / #131313 = Lc −107;
  - #131313 / #F3F3F5 = Lc 98;
  - magenta / #131313 = Lc −34;
  - коды ink 32, лайм 212, magenta 79.

## Палитра в OKLCH

### Анализ seed

- `seed → OKLCH`; относительная хрома `rc`.
- **Ахроматический seed** (C < 0,03) → палитра `mono`:
  - нейтрали без тинта;
  - `accent.action` — инверсный нейтральный: L 0,95 на тёмном, 0,20 на светлом;
  - V04 предупреждает: «монохромная айдентика, фокус — светлотой, размером или материалом».
- **Пара «ахроматика + цвет»** (например `['#000000', '#E4002B']`): чёрный ведёт нейтрали и остаётся `accent.seed` для логотипа, красный становится `accent.action`.

### Режимы палитры (ось `palette`, значения из axes)

| Режим | Хрома нейтралей | Потолок хромы акцента (adaptive) | Настроение по умолчанию |
|---|---|---|---|
| signal | 0,004 | 0,40 | energetic, technical |
| tonal | 0,012 | 0,14 | luxury, editorial |
| duotone | 0,010 | 0,40 | playful |
| pastel | 0,008 | 0,18 | calm |
| mono | 0 | 0,40 | ахроматический seed |
| spectral | 0,010 | 0,20 | — |

- **Хрома нейтралей:** `Cn = min(mode × (0,8 на светлом), 0,5 × C_seed, 0,02)`.
- **Тон нейтралей** = тон seed. Серый рядом с крупным акцентом тянется к его тону, иначе одновременный контраст красит его в дополнительный цвет [И Albers / Chevreul; ресерч цвета §1].

### Нейтральные роли

| Токен | dark | light | Правило |
|---|---|---|---|
| `bg.base` | L = bgL | L = bgL | диапазон core: dark 0,10–0,24, light 0,94–1,00, C ≤ 0,02 |
| `bg.raised` | bgL + 0,045 | bgL + 0,02 → вверх до белого | ≥ 7 яркостных кодов от base (#131313 → #1B1B1B = 8). На светлом у белого кода не хватает → флаг `edge`: карточку определяют `shadow.card` + `line.hairline` (белая карточка на бумаге — 1,11:1 [§6.3]) |
| `bg.sunken` | тёмная лунка ≥ 7 кодов от base, иначе середина между base и raised | bgL − 0,035 (≥ 7 кодов) | инпуты и лунки |
| `bg.overlay` | цвет base с α 0,4–0,7 | то же | скрим. α подбирается так, чтобы `fg.primary` на композите поверх серой (18%) плашки дошёл до target 12:1 |
| `bg.inverse` / `fg.inverse` | бумага L 0,965 / чернила L 0,19 | чернила L 0,17 / бумага L 0,955 | цветовые карточки, смена полярности |

Виньетка для `glow.pool` считается отдельно: base − 0,045, не ниже L 0,10 (класс #0A0A0A).

### Акцент: заливка, fill-only, текст на заливке, текст акцентом

1. **Потолок хромы режима палитры** (только adaptive). Пример: tonal приглушает любой seed до C 0,14 — роскошь не кричит.
2. **Нетекстовый контраст** заливки с фоном: target **3:1 и Lc 30**. Если не проходит:
   - **светлая схема и L ≥ 0,75** (лайм, жёлтый, пастель), `exact` или ахроматика → режим **fill-only**:
     - `accent.edge` — шаг рампы с ≥ 3:1 к фону: обводка 2–4 px или тон тени;
     - `line.focus` = edge;
     - `policy.accent.textAllowed = false`, обводки акцентом ≥ 12 px, площадь ≤ 8%.

     Это обобщение правила Higgsfield «лайм на светлом — только сплошная капсула» [А §6.3];
   - **иначе** заливка сдвигается **от фона**, не дальше ΔL 0,35.
3. **`fg.onAccent`.**
   - Кандидаты: тонированный ink OKLCH(0,17, ≤ 0,035, H), тонированная бумага OKLCH(0,985, ≤ 0,012, H), #000, #FFF.
   - Выбор по уровню (target 4,5 / Lc 60 → floor 3 / Lc 60 → limit 3 / Lc 45), внутри уровня — по |Lc|. Тонированные предпочтительнее.
4. **Мёртвая зона средних тонов** (Y ≈ 0,28–0,36: золото #B8945A, оранжевый #FF7A00). Ни чёрный, ни белый не дают Lc 60.
   - **`adaptive`:** заливка сдвигается **от фона**, не дальше ΔL 0,12 (на тёмном — светлее, под ink). Пример: золото → #D5AB69.
   - **`exact`:** заливка остаётся. Ставится флаг `limit` (floor 3 / Lc 45): текст на акценте только headline-размера, вес ≥ 600; V01 — предупреждение.
5. **`accent.text`** — акцент как текст на `bg.base`: target 4,5 / Lc 60, floor 3 / Lc 45 (между ними — только дисплей ≥ 64 px Bold). Если action не проходит, берётся минимальный сдвиг по рампе. Пример: лайм на светлом → оливковый #657C06, 4,53:1. В режиме fill-only это **другой шаг рампы**, а не заливка: сама заливка текстом не бывает.
6. **Производные цвета:**
   - `accent.actionDeep` = L − 0,30, не ниже 0,20 (губа bevel, тонированная тень);
   - `accent.core` = OKLCH(0,98, 0,25·C, H): для лайма #F2FFD6, ровно ядро Библии;
   - `accent.glow` = action на тёмном; на светлом — шаг L − 0,08 под цветную тень (для лайма #B9E213 ≈ #B8E103 из Библии).

### Вторичный акцент, градиент между акцентами, состояния

- **Вторичный акцент.** `seed[1]` берётся как есть. Иначе: тон H + смещение mood, rc × 0,9, L решается на |Lc| = min(|Lc(accent.text)|, 75). `accent.secondaryText` строится так же, как `accent.text`.
- **Градиент между акцентами** → `policy.accent.secondaryGradient`. Разрешён, только если середина короткой дуги OKLCH лежит в пределах 30° от одного из тонов или её хрома < 0,05 [core 3.16.5]. Иначе акценты разводят нейтралью. Пример: лайм → cyan проходит 174° — нельзя.
- **Состояния** держат свою семью и стоят ≥ 35° от тона акцента. `positive` выбирается из 145 → 165 → 125, `negative` — из 25 → 5 → 45. Решаются на target текста.
- **Правило V19:** |ΔL| ≥ 0,15. Если не выполнено, сдвигается то состояние, которое **сохраняет больше хромы**. Зелёный при осветлении остаётся сочным (на тёмном → мятный), красный — при затемнении (на светлом → винный). Для красных и зелёных брендов, где развести тона нельзя, V04 предупреждает: «добавьте форму или подпись».

### Линии, атмосфера, текстура

- **Линии.** `line.hairline` и `line.strong` — альфа `fg.primary` поверх `bg.base`, двоичный поиск на контраст композита 1,25:1 и 1,6:1. Получается ≈ белый 10% и 18% на тёмном, чернила 11% и 22% на светлом. Отдаются оба значения: rgba и hex композита.
- **Атмосфера.**
  - `atmos.primary`: на тёмном — акцент с α 0,06–0,16 (по glowGain), на светлом — пастельная дымка α 0,46;
  - `atmos.secondary` — то же для вторичного.
- **`glow.pool`** — радиал: центр OKLCH(bgL + 0,075, ≤ 0,05, H) → base на 0,47 W → виньетка. Центр поднимается, пока перепад не станет **≥ 20 яркостных кодов** [Э §6.6]. На светлом — жемчужная дымка.
- **Glow на тёмном.** `glow.action` = 0-offset тень 48 px. Стек ореолов (`detail.glowStack`): ядро + blur 4 / 12 / 32 / 96 / 240 px, gain 0,8 / 0,5 / 0,3 / 0,18 / 0,10 × glowGain [Э G5].
- **Glow на светлом:** `DS(0, 12, 40)`, α 0,25–0,35.
- **Текстура.** `texture.ink` — fg с α 0,08 на тёмном, 0,05 на светлом. `texture.amount` ≤ 0,05 на светлом, на UI — 0.

## Бюджет площади акцента (core `color.areaBudget`)

```
weight = √(|Lc(action, bg)| / 96) · (0,75 + 0,25 · √(C / 0,222))   // лайм на почти чёрном = 1,0
× 1,2, если H в [320…40] или [250…300] (Гельмгольц — Кольрауш)       // пурпурный и синий ярче своего L
weight ∈ [0,5; 1,6];  ext = clamp(1 / weight, 0,6, 1,2)
targetPct = moodTarget × ext;  maxPct = moodMax × ext   (≤ 18; fill-only на светлом ≤ 8; вторичный ≤ 6)
```

- **`policy.accent`:**
  - targetPct, maxPct, objects, echoes;
  - mode (solid | fill-only), textAllowed, strokeMinPx;
  - secondaryMaxPct, secondaryGradient;
  - visualWeight, ext;
  - flood: energetic и playful — ≤ 1 бампер на 15 с, остальные — только end card;
  - counting — правило подсчёта площади акцента (Часть I, цвет), обобщённое на любой акцент.
- **Higgsfield (тема A):** 4% / 8%, 1 + 1 — ровно архивная норма.

## Типографика (core 3.7.6: шкала выводится из пола, а не выбирается)

### Пол → шкала

- **Контексты** (`core.legibility.contexts`, высота буквы в px кадра):

| Контекст | floorX | floorCap | targetX | secondaryX | comfortX |
|---|---|---|---|---|---|
| feed16x9 | 35 | 35 | 35 | 20 | 70 |
| full16x9 | 25,5 | 25,5 | 25,5 | 16,4 | 51 |
| full9x16 / feed1x1 / feed4x5 | 22 | 26 | 26,2 | 17,5 | 44 |
| tv16x9 | 15 | 15 | 22,9 | 15 | 30 |
| desktop16x9 | 10,9 | 14,5 | 10,9 | 10,9 | 21,8 |

- **Несколько контекстов** — берётся поэлементный максимум.
- **Чётное округление:** `floorPx(v)` = чётный px, не больше чем на 2% ниже пола (допуск V06).

**Шаги вывода:**
1. **body** = `floorPx(targetX / xHeight(text-шрифт))`. Пример: Inter 0,546 → 64; Jost 0,46 → 76; Commissioner 0,496 → 52 в 9:16.
2. **steps[k]** = round(body × ratio^k). Если округление ломает ×1,333, шаг поднимается.
3. **headline** — первый шаг, где высота буквы display-шрифта ≥ comfort и строка из N знаков влезает в живую ширину (N = 18 в 16:9, 12 в вертикальных форматах [§5.7]). На тёмной схеме в feed16x9 headline ≥ 120 px — dark-scene uplift [core 3.8.4].
4. **display** = headline + 2 шага; **mega** = display + 2 шага (≤ 680 px). Оба опускаются на шаг, пока не влезет 10 (6) и 4 (3) знака. **subhead** = headline − 1 шаг.
5. Остальные роли:
   - **label** = floorCap / capHeight (CAPS);
   - **caption** = max(минимум субтитров формата, body);
   - **ui** = max(20, 0,56 × body);
   - **code** = body × xHeight(text) / xHeight(mono): моно на той же высоте строчных, что и body.
6. **`policy.type.framePairs`** — пары ролей с отношением ≥ 2: только они могут стоять в одном кадре [core 3.6.3].
7. **Поля каждого `type.*`:** family, designFamily, weight, size, lineHeight, trackingEm/Pct, case (upper | sentence), features, role (mustRead | secondary | texture), minPx, targetPx, maxCharsPerLine, letterPx, opsz.

### Трекинг: таблица голоса, зажатая в полосу core

- Значение берётся из таблицы голоса (axes: строки [minPx, caps, sentence], первая подходящая) и зажимается в полосу core `typography.trackingBySize`.
- Коррекции:
  - светлые CAPS на тёмном при 96–130 px получают +0,01 em (иррадиация);
  - голоса с `noNegativeTracking` (Doto, DotGothic16) никогда не уходят в минус: точки слипаются. V11 по ним — предупреждение.
- Число зажатых ролей пишется одной строкой в `meta.fixes`.

| px | 20–47 | 48 | 85 | 114 | 152 | 202+ |
|---|---|---|---|---|---|---|
| grotesk-tech, sentence / CAPS | 0 / +12% | −2 / −2 | −3 / −3 | −3 / −3 | −4 / −4 | −5 / −4 |
| didone-luxury | 0 / +12 | −1 / −2 | −2 / −2 | −2 / −2 | −3 / −3 | −4 / −3 |
| pixel (Doto) | +2 / +6 | +2 / +3 | +2 / +2 | +2 / +2 | +2 / +2 | +2 / +2 |

Капитель 48–80 px — это **киккер** (−2…−4%, архив). Разрядка +4…+12% допустима только для меток 20–47 px.

### Интерлиньяж, веса, письменности

- **Интерлиньяж** — значения голоса, зажатые в полосы core:
  - CAPS-заголовок 0,88–1,0;
  - смешанный дисплей 1,0–1,11;
  - body 1,3–1,4;
  - подпись 1,2;
  - code 1,4;
  - метка-капитель 0,8–0,9.
- **Веса.** Прижимаются к доступным начертаниям. `weight.body` ≥ 500; `weight.strong` = body + 200.
- **Письменности.**
  - Нет нужного сабсета на Google Fonts → **вся роль** переставляется в замену, скрипты не смешиваются внутри слова.
  - Кегли пересчитываются по метрикам замены.
  - `font.fallback.{Cyrl, Grek, Jpan, Kore, Hans, Hant, Arab, Deva}` отдаются всегда, со `sizeAdjust` (совпадение по cap-height для CAPS, по x-height для строчных) — для переноса латинской вёрстки.
  - Предпочтения для кириллицы: Space Grotesk → Inter Tight · Space Mono / DM Mono → JetBrains Mono · Plus Jakarta Sans → Manrope · Fraunces → Literata · Bricolage → Onest · Doto → DotGothic16.
  - Остальные письменности: Noto Sans / Serif JP, KR, SC, TC; Noto Sans / Kufi / Naskh Arabic; Noto Sans / Serif Devanagari.
- **`FONT_DB`.** Письменности и оси — из Google Fonts metadata API; x / cap / ширина — из OS/2 через @capsizecss/metrics (2026-10-08). У Noto Naskh Arabic нет OS/2 x и cap, взяты значения Noto Sans.

## `HFT.validate()`: правила V01–V21

Канонические формулировки правил — в core (`core.json → validation`); здесь — как их проверяет derive. ## Интеграция и расхождения между слоями

**Порядок интеграции в `hf-tokens.js`:**
1. `HFT.derive = derive`.
2. Заглушки `CORE`, `FONT_DB`, `TYPE_VOICES`, `PALETTE_MODES`, `MOTION`, `COMPOSITION`, `DENSITY`, `TEXTURE` заменяются чтением `core` и `axes`. derive читает только поля, перечисленные в заглушках.
3. `theme(nameOrSpec)` = derive(seed, mood пресета или бренда) → overrides → повторный `validate()`.
4. Бренд Higgsfield хранит свои точные значения как override: #0B0B0D / #FAFAFF, #A2A2A2, #131313, капсулу S1.

**Расхождения axes ↔ core.** derive их зажимает и логирует; нужно решение одной строкой в одном из слоёв:

| Где | axes (`_work/axes.py`) | core | Что делает derive |
|---|---|---|---|
| Трекинг didone-luxury | CAPS +4…+12% на дисплее («разреженная капитель») | CAPS ≥ 48 px: −0,02…−0,07 em | зажимает (V11 fix). Если люксу нужна разрядка, расширьте полосу core для didone |
| Трекинг pixel (Doto) | +2% всегда, минус запрещён | CAPS ≥ 48 px ≤ −0,02 em | держит ≥ 0 (точки слипаются); V11 warn |
| Бюджет акцента по настроениям | energetic 6–15 / max 25, playful 12–30 / max 40 | 7 / 12 и 8 / 14; потолок 18 | следует core |
| Формы | soft: chip 10, button 14 | soft: control 0,25 h, chip 0,25 h | следует core |
| Overshoot | productive 6%, expressive 10%, playful 15% | 0 / 0,06 / 0,12 | следует core |
| durMul luxury-slow | 1,6 | m ≤ 1,8 | при energy 0,15 даёт m 2,14 → 1,8 (fix) |
| hold expressive | holdMult 0,9 | hold никогда не ниже 1 | 1,0 (fix) |
| Камера glitch-tech | `linear` | симметричный in-out | [0,65, 0, 0,35, 1] (fix) |
| Режим палитры tonal | потолок хромы акцента 0,14 | `accentMinChroma` 0,10 (V04 warn) | тусклые seed (золото, лес) получают warn, а не правку |

**Границы прототипа:**
- только sRGB / Rec.709, без P3 и HDR;
- контраст текста поверх генераций — по худшему пикселю под глифами, скрим 40–70% (Часть I: текст поверх изображения); derive знает только «средний кадр» для `bg.overlay`;
- кастомные оси (`FLAR`, `SOFT`, `ROND`) в `fontLink` не выводятся;
- `FONT_DB` — снимок от 2026-10-08, его нужно обновлять при добавлении голосов.

**Эвристики [Э] для ревью стайлбордов** (кандидаты на проверку по реальным кадрам):
- bgL и glowGain настроений;
- формула веса акцента («Бюджет площади акцента»);
- выбор «правее по хроме» для состояний («Вторичный акцент…»);
- α скрима над серым 18% («Нейтральные роли»).
